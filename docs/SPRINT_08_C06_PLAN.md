# Sprint08 P4 — конечный остаток списка журналов

Предложение нового плана, до голосов не разрешает менять принятую реализацию. Окно Sprint08 прежнее: 03:42–09:42 UTC. Версия0.6.0/source281d13dd и отдельное принятие R3-03 остаются неизменными.

Цель: устранить реальный пробел исходного R2-C06 — дата и состояние в списке журналов. После независимой проверки всех восьми исходных сценариев можно предложить отдельное принятие R2-04; оно не обещано заранее и не закрывает весь R2. Canonical service, SplitMiner, общий audit policy/result и cleanup не входят в новое изменение.

## Контракт до реализации

- StoredLog получает optional `created_at: DateTime<Utc>`: новое серверное UTC-время подготовки успешной публикации результата, записанное атомарно вместе с ним. Это дата сохранения в приложении, не время событий или файла. Все пути создания используют общую точку insertion: обычный XES, CSV, preview confirmation и job publication. Входной запрос не задаёт это поле.
- Старое отсутствие поля сохраняется как отсутствие; в списке явно «Дата не сохранена». Не вычислять дату из ID, имени файла, timestamp событий, времени миграции или текущего старта. Restore сохраняет исходное поле, редактирование и restart не обновляют его.
- Явное неправильное значение даты отклоняется строгим decoder. Неизвестные поля остаются запрещены. Допустимая дата экспортируется в RFC3339 UTC и показывается человеку в UTC; исходная provenance дата/UUID не подменяется этим полем.
- Каждая строка содержит HTML-escaped имя, прежний стабильный ID, число событий, дату и состояние «Сохранённый анализ». Это состояние опубликованного результата, а не обещание целостности нечитанного payload. Пояснение рядом: «Целостность данных проверяется при открытии; незавершённые обработки находятся в задачах». Не включать running/failed jobs в список готовых журналов.
- Список читает только малые метаданные; не загружает тяжёлые log_data/log_source/log_analysis ради даты или состояния. Права и ограничения проекта сохраняются. Отсутствующая/повреждённая обязательная запись остаётся fail-closed при открытии; «проверен/исправен» не отображается без фактической проверки.
- Новый кандидат0.6.1: новый source/EXE/ZIP, новая независимая приёмка и отдельная публичная поставка. Старые пользовательские установки, включая0.6/3061/5441, не изменять и не обновлять автоматически. Downgrade нового поля не обещан; использовать backup/new restore.

## Конечные проверки

1. Два одинаковых filename, разные IDs, результаты и параметры; серверные даты в захваченных пределах создания, точные значения строки/UTC/state/escaping. Открытие/экспорт каждой строки ведёт к своему результату.
2. Все четыре producer paths задают дату; каждый успешный результат имеет сохранённый state. Неудачный/отменённый job не создаёт строку; accepted cancellation/recovery проверены на текущем новом кандидате либо переиспользуются только при доказанной идентичности полного затронутого пути.
3. Restart, изменение представления и backup/newrestore сохраняют дату/IDs/counts/результаты/исходник/историю. Полные row values/versions сверены; payload не переписывается ради списка.
4. Legacy отсутствующее поле читается и явно unknown; malformed дата/refusal без частичной SQL-записи; strict serde и канонический encoder остаются. Исторические значения не выдуманы.
5. Viewer читает, чужой пользователь не читает; duplicate listing/metadata-only SQL не загружает heavy payload. Полный актуальный ledger R2-C01–08 отдельно reviewed, narrow genuine reference scope явно указан.
6. Frozen build, fmt/clippy/обычные тесты, meaningful created_at/legacy/render/producer регрессии, actual native package/PG/browser/public fullZIP+manifest/newinstall/protected postchecks, actual CI, новые голоса точной приёмки. Игнорируемые PG tests не объявлять executed; ошибки verifier/exitcapture сохранять.
