# Общий вычислительный модуль оценки BPMN

`src/bpmn_quality/` содержит прежние bridge, граф разметок, fitness, precision,
simplicity, типы ошибок и лимиты. Вычисления перенесены из `examples/quality/`;
адаптеры примеров обращаются к одной реализации библиотеки. Новый workspace
и новая математическая методика не вводятся.

## Использование и границы

Прежние команды сохранены:

```text
cargo run --locked --example bpmn_quality -- prepare fixtures/quality/corpus.json NEW_PREPARED
cargo run --locked --example bpmn_quality -- score NEW_PREPARED NEW_METRICS.json
```

CLI остаётся отдельным диагностическим инструментом: он читает фиксированный
корпус и пишет новые файлы. Корпуса, файловый ввод/вывод и проверка происхождения
остались в адаптере. Новый `sources()` включает четыре фактически исполняемых
файла библиотеки, а не только адаптеры. Старые свидетельства не переписаны.
Подготовленные пакеты привязаны к точным исходникам: для другой сборки нужен
новый `prepare`; отказ нового `score` читать старый пакет не обходится заменой
хешей. Форматы пользовательских проектов и БД этим переносом не меняются.

Низкоуровневый Rust API требует согласованных проверенных входов:
`bridge::from_xml` / `from_model` → `state::admit` → `metrics::score`.
Граф вычисляется из той же сети. Произвольный десериализованный `Graph` нельзя
считать доверенным только потому, что его Rust-тип совпал. Проверенный фасад,
фоновые задания и пользовательская форма — следующий инкремент; новая кнопка
этим изменением не объявляется.

Прежние пределы сохранены: 64 трассы, 500 событий, 32 варианта, 64 события
в трассе, 200 байт в метке; 128 узлов и 256 дуг сети; 10 000 разметок,
100 000 состояний поиска fitness/prefix, 10 000 состояний tau-замыкания.
Это конечные алгоритмические ограничения, а не измеренная общая гарантия RAM
или времени ответа. Диагностический отчёт содержит подробные свидетельства.

`no_data`, неподдерживаемая семантика, `requires_fitting_log` и исчерпание
лимитов сохраняются без выдуманных оценок. Structural simplicity характеризует
структуру представленной сети, а не доказывает корректность процесса.
Оценка журнала не доказывает, что он независим от данных обучения.

## Проверка переноса

Проверены прежние четыре quality-теста, три теста miner-cohort, все цели
компиляции и сборка обоих CLI. Свежий `prepare`/`score` на общем модуле дал
34 случая, 54 пары «случай × модель» и 84 группы. Оценки, статусы, входы,
структура сетей и свидетельства precision сравниваются с исходными данными
с точным различением типов JSON. Исторический бинарник использован как
дополнительный контроль: шесть файлов оценщика совпадали с исходниками до
переноса, но его `Cargo.lock` отличался; он не назван той же новой сборкой.

Равноценные оптимальные alignment-пути могут различаться даже между запусками
неизменённого старого бинарника. Первый чрезмерно строгий аудитор отверг такое
различие; отказ сохранён. Скорректирована только проверка равенства маршрута
и диагностического числа посещённых состояний: стоимости и остальные данные
остались точными, оба маршрута независимо выполнены и проверены на оптимальность
по графу. Также проверены сохранность сети, точные дроби и tau-префиксы.
Исторический PM4Py-результат не перепривязан к новому пакету и не выдан за новый
запуск upstream.

Четыре отрицательных опыта отвергнуты: `false` вместо численного нуля,
изменённая fitness, неверный переход при прежней заявленной стоимости и
повторный ключ JSON. Повреждённый переход отверг именно независимый проверяющий
маршрута, а не сравнение текстов.

## Независимое повторение без Rust и Java

Пакет `evidence/sprint25/quality/quality-evidence.zip` хранит точные исходные байты
свежей подготовки, результата и аудита. Это обычная ZIP-упаковка свидетельств,
без сокращения чисел или отчёта. Manifest перечисляет все 118 файлов, их размеры
и SHA; развёрнутый объём — 11 702 530 байт, архив — 344 412 байт.
Приватные сырые захваты процессов, бинарники и учётные данные в него не входят.

Из корня проекта с Python 3, в новый каталог:

```text
python -B tests/sprint25_quality_shared.py --output .local/sprint25/quality-replay
```

Проверяющий сверяет весь архив, пути, типы файлов и хеши трёх аудиторов,
затем повторяет независимый расчёт и четыре повреждения. Он отказывается
перезаписывать существующий каталог. Это повтор проверки сохранённых
свидетельств; новый запуск miner или PM4Py здесь не выполняется.

Публичная приёмка конкретного коммита, CI и факт слияния фиксируются отдельно
в PR. Общая готовность P1, интерфейс и восстановление заданий этим документом
не объявляются.
