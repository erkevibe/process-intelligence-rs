# Общий вычислительный модуль оценки BPMN

`src/bpmn_quality/` содержит прежние bridge, граф разметок, fitness, precision,
simplicity, типы ошибок и лимиты. Вычисления перенесены из `examples/quality/`;
адаптеры примеров обращаются к одной реализации библиотеки. Новый workspace
и новая математическая методика не вводятся.

## Использование и границы

Прежние команды сохранены:

```text
cargo run --locked --example bpmn_quality -- prepare fixtures/quality/corpus.json NEW_PREPARED
cargo run --locked --example bpmn_quality -- score NEW_PREPARED NEW_METRICS.json
```

CLI остаётся отдельным диагностическим инструментом: он читает фиксированный
корпус и пишет новые файлы. Корпуса, файловый ввод/вывод и проверка происхождения
остались в адаптере. Новый `sources()` включает четыре фактически исполняемых
файла библиотеки, а не только адаптеры. Старые свидетельства не переписаны.
Подготовленные пакеты привязаны к точным исходникам: для другой сборки нужен
новый `prepare`; отказ нового `score` читать старый пакет не обходится заменой
хешей. Форматы пользовательских проектов и БД этим переносом не меняются.

Низкоуровневый Rust API требует согласованных проверенных входов:
`bridge::from_xml` / `from_model` → `state::admit` → `metrics::score`.
Граф вычисляется из той же сети. Произвольный десериализованный `Graph` нельзя
считать доверенным только потому, что его Rust-тип совпал. Приложение вызывает
проверенный фасад, описанный ниже, и не принимает граф или сеть от HTTP-клиента.

Прежние пределы сохранены: 64 трассы, 500 событий, 32 варианта, 64 события
в трассе, 200 байт в метке; 128 узлов и 256 дуг сети; 10 000 разметок,
100 000 состояний поиска fitness/prefix, 10 000 состояний tau-замыкания.
Это конечные алгоритмические ограничения, а не измеренная общая гарантия RAM
или времени ответа. Диагностический отчёт содержит подробные свидетельства.

`no_data`, неподдерживаемая семантика, `requires_fitting_log` и исчерпание
лимитов сохраняются без выдуманных оценок. Structural simplicity характеризует
структуру представленной сети, а не доказывает корректность процесса.
Оценка журнала не доказывает, что он независим от данных обучения.

## Проверка переноса

Проверены прежние четыре quality-теста, три теста miner-cohort, все цели
компиляции и сборка обоих CLI. Свежий `prepare`/`score` на общем модуле дал
34 случая, 54 пары «случай × модель» и 84 группы. Оценки, статусы, входы,
структура сетей и свидетельства precision сравниваются с исходными данными
с точным различением типов JSON. Исторический бинарник использован как
дополнительный контроль: шесть файлов оценщика совпадали с исходниками до
переноса, но его `Cargo.lock` отличался; он не назван той же новой сборкой.

Равноценные оптимальные alignment-пути могут различаться даже между запусками
неизменённого старого бинарника. Первый чрезмерно строгий аудитор отверг такое
различие; отказ сохранён. Скорректирована только проверка равенства маршрута
и диагностического числа посещённых состояний: стоимости и остальные данные
остались точными, оба маршрута независимо выполнены и проверены на оптимальность
по графу. Также проверены сохранность сети, точные дроби и tau-префиксы.
Исторический PM4Py-результат не перепривязан к новому пакету и не выдан за новый
запуск upstream.

Четыре отрицательных опыта отвергнуты: `false` вместо численного нуля,
изменённая fitness, неверный переход при прежней заявленной стоимости и
повторный ключ JSON. Повреждённый переход отверг именно независимый проверяющий
маршрута, а не сравнение текстов.

## Независимое повторение без Rust и Java

Пакет `evidence/sprint25/quality/quality-evidence.zip` хранит точные исходные байты
свежей подготовки, результата и аудита. Это обычная ZIP-упаковка свидетельств,
без сокращения чисел или отчёта. Manifest перечисляет все 118 файлов, их размеры
и SHA; развёрнутый объём — 11 702 530 байт, архив — 344 412 байт.
Приватные сырые захваты процессов, бинарники и учётные данные в него не входят.

Из корня проекта с Python 3, в новый каталог:

```text
python -B tests/sprint25_quality_shared.py --output .local/sprint25/quality-replay
```

Проверяющий сверяет весь архив, пути, типы файлов и хеши трёх аудиторов,
затем повторяет независимый расчёт и четыре повреждения. Он отказывается
перезаписывать существующий каталог. Это повтор проверки сохранённых
свидетельств; новый запуск miner или PM4Py здесь не выполняется.

Ядро принято и включено в `main` через
[PR37](https://github.com/erkevibe/process-intelligence-rs/pull/37), коммит
`c1840b4d0204e2951e09c6c62c560047d84b0dbd`. Обе проверки принятого head
`4b170d7c62a3263771b9dc0935a8fc2292679aaf` прошли по 31 шагу, включая новый
расчёт Rust на Linux. Все 7056 файлов публичного Git-архива совпали с коммитом;
скачанный проверяющий повторил 34/54/84 и четыре отказа.

## Фасад приложения и предпросмотр

`bpmn_quality::facade::evaluate_model` принимает сохранённую BPMN-модель,
строки вариантов и только уменьшенные пределы. Он ограничивает модель
128 узлами, 256 переходами и 1 MiB её JSON до построения сети, проверяет
число трасс, событий, вариантов и размеры меток до копирования строк.
XML-вход также ограничен 1 MiB. Граф строится внутри из той же сети.

Профиль `application_bounded_v1` ограничивает граф разметок, fitness,
префиксный поиск и tau-замыкание 1000 состояниями. Он может завершиться без
оценки там, где прежний диагностический профиль получил число. Пределы CLI
не изменены. Compact precision выполняет тот же расчёт, но не создаёт и не
сохраняет JSON-свидетельства поиска для каждого префикса. Сравнение на всех
84 прежних группах при одинаковых пределах сохраняет числа и статусы.

Отчёт содержит три метрики, профиль, пределы и SHA256 модели, сети и
канонических вариантов. Хеш модели относится к JSON сохранённой модели,
а не к исходному XML. Суммирование одинаковых вариантов и сортировка дают
одинаковую идентичность независимо от порядка строк входа. Совпадение или
различие журналов само по себе не устанавливает независимость данных обучения.

Полезная часть отчёта и ошибки фасада ограничены 64 KiB; частичные графы
и подробные диагностические ошибки в приложение не передаются. Это предел
сериализованного ядра отчёта, а не общего HTML, памяти процесса или всей
HTTP-оболочки с именами ресурсов. Проверки остановки выполняются между этапами
и префиксами; отдельный вызов upstream alignment нельзя мгновенно прервать.
Граница 30 секунд в предпросмотре проверяется в этих точках и не является
жёсткой гарантией времени ответа.

В модели есть переход «Оценить модель». Форма выбирает текущий журнал проекта;
оценивается его полная сохранённая отфильтрованная `data`, без скрытой выборки.
Порог картинки и пользовательский выбор отдельной трассы не меняют вход.
Редактор и владелец могут считать, наблюдатель — просматривать форму.
Повторный запрос убирает старые числа до начала расчёта. Datastar заменяет
панель результата; обычная отправка формы остаётся запасным путём.
Отказы показывают причину, а не прежний успешный результат.

POST `/models/{id}/quality` принимает `log_id` и `revision`. Для JSON-ответа
нужен `Accept: application/json`. Оболочка содержит точные версии модели и
анализа журнала, их имена и признак оценки на журнале построения.
`Datastar-Request: true` получает SSE-панель; отказ операции внутри обработчика
передаётся успешным SSE-транспортом с текстом отказа. JSON API сохраняет
HTTP 403/404/409/422/503. Отказы общего middleware также обрабатываются
клиентом как отсутствие новой оценки.

Расчёт использует общие два места операций и вычислительные разрешения.
Разрешения, включая допуск к данным, удерживает фактический blocking worker,
даже если клиент закрыл HTTP-запрос. Перед выдачей повторно проверяются права,
проект, ревизия модели, версия анализа и исходный SHA журнала; ответ строится
под блокировкой актуальных прав. Последующее получение уже отправленного
ответа не является мгновенным отзывом ранее выданных байтов.

Предпросмотр не создаёт постоянного задания, результата или записи истории.
После перезапуска повторный расчёт нужно запустить явно. Форматы Repository,
Header, записей PostgreSQL и DDL этим инкрементом не расширяются. Общий P1
остаётся открыт: далее нужны сохраняемый отчёт, постоянные задания, отмена,
аварийное восстановление и отдельная проверка старого бинарника при таком
расширении. Фактическая приёмка предпросмотра, браузера и конкретного коммита
фиксируется в его PR; компиляция сама по себе её не заменяет.
