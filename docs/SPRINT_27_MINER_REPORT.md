# P2: сравнительный эксперимент и выбор ограниченного Rust-кандидата

24 октября2026. Выбран `structured_variants_v1` для следующего инкремента
продуктовой интеграции. Это собственная ограниченная эвристика на Rust,
**не порт SplitMiner и не полная реализация Inductive Miner**. В этом изменении
сервер ещё использует прежнее построение; фоновые задания и UI нового пути
остаются следующим инкрементом. P2 целиком пока не закрыт.

## Что сравнивали

Три малых синтетических корпуса закреплены до соответствующих новых запусков:
[первый](MINER_EXPERIMENT.md), [validation](MINER_VALIDATION_PHASE.md),
[третий для нативного кандидата](MINER_STRUCTURED_PHASE.md).
Новый контроль не передавался функции построения. У Python/Java отдельный
процесс получал только обучающий XES; у Rust функция получала только training
variants, а оценка контрольных данных выполнялась после построения.

Восемь закрытых серий содержат168 запусков, по два повтора каждого сочетания
алгоритма/корпуса/случая. Это не168 независимых статистических испытаний:
часть запусков отвечает `no_data`, а случаи и повторы зависимы. Отдельные
процессы оценивали10 Java-моделей и24 Python-модели. Математический модуль
сервера не переписан; использовался принятый фасад с профилем1000 состояний.

| Алгоритм/настройки | Linear control fitness | XOR | Невиданный параллельный порядок | Больше self-loop повторов | Больше short-loop повторов |
| --- | ---: | ---: | ---: | ---: | ---: |
| Прежний observed | 1 | 1 | 0.8 | 0.875 | 5/6 |
| Rust Alpha+++, прежний developer profile | 1 | 1 | отказ | отказ | отказ |
| Rust Alpha+++, upstream default | 1 | отказ | 0.8 | отказ | отказ |
| Rust Alpha+++, repair без DFG-фильтра | 1 | 1 | отказ | отказ | отказ |
| Настоящий Java SplitMiner | 1 | 1 | 0.75 | standard loop вне поддержанного subset | 2/3 |
| Настоящий Python PM4Py IM | 1 | 1 | 1 | 1 | 1 |
| Собственный structured_variants_v1 | 1 | 1 | 1 | 1 | 1 |

Таблица относится к первому корпусу и конкретным закреплённым параметрам.
Прежний Alpha profile отключал ремонт; его отказы не характеризуют все
настройки библиотеки. Default и отдельный repair profile проверены дополнительно
на заранее закреплённом validation. Отказы сохранены с кодами причин.
На пустом журнале Java действительно получил исключение, оно не заменено
выдуманным успешным исходом. Неподдержанный standard-loop не был удалён из
диаграммы ради численной оценки.

## Что определило выбор

Нативный кандидат прошёл42 запуска на21 случае:36 моделей и6 `no_data`.
В каждом повторе совпали модель и метрики. Для каждой из36 конкретных конечных
сетей проверены WF structure, one-safety, option-to-complete, proper completion
и отсутствие dead transitions. Независимый process-tree epsilon-NFA/shuffle
проверил полный наблюдаемый язык основного JSON, сети, фактического XML и
повторно импортированного JSON. Это не ограниченное перечисление коротких трасс.
Все76 численных групп совпали с неизменённым PM4Py2.7.17 reference.

У PM4Py IM подтверждены52 численные группы и правильность преобразований,
но **нарушен критерий повторяемости**. На `two_parallel_chains` первый результат
был `A → AND(C,E,B,D) → F`, второй — `A → AND(C,B,sequence(D,E)) → F`.
Fitness контроля равен1 в обоих случаях, precision равна7/12 и2/3,
simplicity —6/7 и23/25. Полная проверка языка нашла свидетельство
`A B C E D F`: первая модель принимает его, вторая отвергает.
Завершение аудитора с этим наблюдением не означает допуска IM.

Качество нативного кандидата сопоставимо с IM на рассмотренных примерах,
его повторяемость подтверждена, а поставка сохраняет один Rust-сервис без
добавления Python или Java runtime. Выбор ограничен этой областью входов;
он не устанавливает универсальное превосходство алгоритма.

## Ограничения качества и ресурсов

- Precision не становится1 вслед за fitness: обобщённая модель разрешает
  дополнительные порядки и повторения. В третьем случае с повторной меткой
  внутри ветвей precision0.5 сохранена в отчёте. Фильтра шума нет.
- Неизвестная control activity даёт ожидаемый fitness около0.9333 и
  `requires_fitting_log` без числа precision. Другой журнал сам по себе
  не доказывает независимость выборки; корпуса здесь заданы явно.
- Пределы:6 обучающих activities,64 трассы,500 событий,32 варианта,
 64 события в трассе,64 узла/128 flows для нативной модели. Каждая отдельная
  оценка имеет кооперативный срок30 секунд; весь новый native example —
  внешний срок60 секунд и512MiB private commit на процесс.
- Наблюдённый максимум retained-image working set нативного кандидата —
  около5.82MiB, private commit —1.21MiB. Процесс включает построение,
  преобразование, экспорт и оценки; это не оценка всей будущей серверной нагрузки.
- Java JVM показала до194.84MiB working set и581.39MiB private commit
  при heap512MiB. У Python venv измеренный image оказался redirector:
  PID-контроль подтвердил отдельный interpreter PID. Поэтому его engine
  CPU/RAM **не установлены** этими счётчиками, маленькие launcher-значения
  не используются для сравнения. Wall time учитывает ожидание дочернего
  процесса. Process-tree totals не измерены; скоростного рейтинга нет.

Source metadata: собственный код — MIT; `process_mining0.6.2` —
MIT OR Apache-2.0; заголовок фактического класса SplitMiner указывает
LGPL-3.0-or-later, однако весь202-entry Java runtime требует отдельного
просмотра зависимостей перед распространением. Установленный PM4Py2.7.17
указывает AGPL3. Эти внешние runtime этим изменением не поставляются.

## Проверка доказательств

Независимый проверяющий закрыл source review и численную приёмку нативного
кандидата, отдельно подтвердил воспроизводимость отказа IM. При проверке самих
аудиторов исправлены обязательность групп, strict numeric types, связь с raw
frozen corpus, actual XML/reimport language и exact raw-byte identity net files.
20 positive/counterfactual controls отвергли coherent train/control swap,
bool вместо числа, неверные хеши/счётчики, пропущенный held-out и модель/XML
другого процесса. Старая неудачная попытка не переименована в успешную.

Публичный пакет:
[`evidence/sprint27/miner-comparison`](../evidence/sprint27/miner-comparison/).
Он содержит168 строк,55 папок моделей (включая отличающийся второй IM-результат),
исходные входы оценки, компактные результаты, эталонные оценки, конечные сети,
графы и безопасные проекции receipts. Сырые private HTTP/cookie/classpath logs
не публикуются. Проверка стандартной библиотекой Python:

```text
python -I -B tools/sprint27/audit-public-miner.py evidence/sprint27/miner-comparison
```

Она повторяет conservation, сохранённые языковые сравнения, strict agreement
с записанным reference и точную привязку к корпусу. Она не запускает майнер,
не удостоверяет автора и не заменяет отдельно записанное выполнение настоящего
PM4Py XML converter. Фиксированные byte-pins сохранены через `.gitattributes`.

Следующий инкремент — [контракт заданий построения](DISCOVERY_JOBS_CONTRACT_DRAFT.md):
сохраняемый вход, общий CPU/очередь, атомарная публикация модели, отмена,
перезапуск/повтор, точная training identity, миграция, backup/restore и браузерный
сценарий с отдельным контрольным журналом. Этот документ не объявляет их готовыми.
