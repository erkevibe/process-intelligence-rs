# Нативный ограниченный кандидат structured_variants_v1

Предложение фиксируется до реализации и первого запуска этого кандидата.
Alpha+++ и Java SplitMiner на прежних корпусах уже имеют явные ограничения.
PM4Py IM проверяется отдельно; Python/AGPL не объявляется нативной поставкой.

Новый собственный Rust-кандидат строит небольшое структурное дерево по вариантам:
пустое действие, задача, последовательность, XOR, AND, повтор один-или-более.
Это не порт SplitMiner и не полная реализация Inductive Miner. Порядок правил:
пустые варианты → примитивный повтор одного слова → XOR по совместной
встречаемости → последовательные блоки DFG → параллельные блоки по обоим
наблюдавшимся относительным порядкам → точный XOR наблюдавшихся вариантов.
Последний случай сохраняет ограниченность базового observed подхода и явно
помечается в provenance; никаких подставных fitness/precision.

Все решения детерминированы по отсортированным меткам. Частоты не отбрасываются,
фильтра шума нет. Рекурсия/размер дерева/модели, 6 activities,64 traces,500 events
ограничены до дорогой обработки. Внешний процесс:60s,512MiB private commit.
Оценщик не меняется. Проверяем конкретную конечную сеть на one-safety,
option-to-complete, proper completion и отсутствие dead transitions.

Помимо двух прежних корпусов заранее фиксируется третий
`fixtures/sprint27-structured/corpus.json`: вложенные циклы/ветвления,
параллельная необязательная задача, иной набор параллельных перестановок,
чужая контрольная activity. Контроль не используется в построителе.
Одна хорошая выборка не становится гарантией произвольных журналов.

Сначала эксперимент, независимая сверка языка и метрик, затем решение об
интеграции. Не менять правила или пороги после результатов без новой фазы
и нового заранее закреплённого контроля. Сравнение сохраняет все отказы.
