# Sprint33: v5→v6 через CLI под обычной ролью PostgreSQL

Статус: новый кандидат P3 после принятого [PR45](https://github.com/erkevibe/process-intelligence-rs/pull/45), main `cb22669c33feab90986e3d8b0f59d247316d31c6`. Реализация прошла статическую проверку; успешное выполнение ещё не заявлено. Исходные сценарии [служб](SPRINT_31_REPORT.md) и [повторной миграции v6](SPRINT_32_REPORT.md) сохраняются без изменения.

Повтор v6 проверяет подключение и чтение, но не исполняет CREATE TABLE новой схемы. Поэтому отдельная свежая Ubuntu24.04 VM проверяет настоящий переход CLI v5→v6 с LoadCredential под `pi_s31_app`: без superuser/createdb/createrole, с владением собственной базой и восстановленными объектами.

В третью заранее отсутствующую базу полностью копируется богатая синтетическая база предыдущих сценариев. Полный снимок сначала должен совпасть с источником. Только в этой третьей копии конструируется v5: удаляются таблица учёта, строка версии6 и поле политики квоты во всех заголовках. Это подготовка искусственной fixture по известному контракту, а не откат рабочей базы и не доказательство исполнения старого writer. Удаление строки версии не является допустимым способом production rollback.

Перед CLI проверяются точные ledger1…5/checksums, отсутствие quota table и политики, а также равенство всех остальных данных и схемных объектов источнику за явно перечисленными отличиями. После CLI обратная проекция полного снимка должна точно совпасть с v5; новая таблица/ограничения/индексы — с ожидаемой v6, строка6 получает прежние name/checksum и другую отметку применения. Владельцем реально созданной таблицы должен быть обычный пользователь приложения.

Независимый Python пересчитывает все записи каждого проекта, счётчики и реестр cost/version. Выбранные синтетические записи сохраняются отдельно для повторного расчёта без PostgreSQL; глобальные учётные данные и сессии в этот файл не входят. Повторная CLI-команда после обновления должна быть точным no-op. Новые процессы служб проверяют прежний отчёт и права наблюдателя; политика квоты по умолчанию выключена, поскольку в v5 её не было. Прежние ожидания quota0 предыдущего сценария не переопределяются.

Десять критериев: отсутствие третьей базы; точная копия; роль и владение; точная v5 fixture; реальное создание v6 с сохранением проекции; независимый учёт; повтор без изменений; новый процесс/отчёт/права/default-off; отсутствие известных секретов в журналах; остановка и возврат исходного credential. Содержимое исходной базы сверяется до и после; credential возвращается только после остановки обеих служб, его точные байты сверяются приватным отпечатком.

Наблюдения третьей фазы отделены от строгих протоколов Sprint31/Sprint32. Общий firewall удаляется один раз после подтверждённой остановки всех собственных units. Ошибочная fixture отбрасывается вместе с VM. Публикуются выбранные JSON и синтетические записи учёта, без дампов, секретов и raw-журналов. Короткий CLI сохраняет честную границу: настройки unit и коды завершения, без выдуманного наблюдения его `/proc`.

Этот инкремент не заменяет приёмку реального исторического экспорта организации, другой версии PostgreSQL или целевого production-хоста. Пользовательский сервис3131 и локальные экземпляры PostgreSQL/app не используются. Граница текущего окна остаётся25.10.2026 01:34:03UTC.
