# Квота проекта: контракт кандидата Sprint30

Статус: проект решения до реализации и проверки. Производственный предел не выбран.

Метрика `structural_bytes_v1` — логические единицы, не размер JSON, диска или
памяти. UTF-8 строки и ключи считаются по числу байтов; null и bool стоят 0,
любое конечное число — 32, массив — 7+4*N+стоимость элементов,
объект — 7+8*N+стоимость ключей и значений. Запись стоит дополнительно
32+UTF8(kind)+UTF8(resource_id). Учитываются все восемь видов records.
Арифметика проверяется на переполнение. Варианты записи одного числа не
влияют на стоимость; дубли ключей не являются отдельными хранимыми данными.

Общая квота состоит из фиксированного резерва заголовка
`(1<<28)-(64<<10)` и явно заданного allowance записей. По умолчанию лимит
выключен. Это сознательно крупный резерв существующего формата, а не
рекомендация размера проекта. Заголовок, политика и аудит не получают
неограниченного исключения: действуют его строгие лимиты и проверка структуры.

Внутри резерва заголовка постоянно оплачено 32MiB для всей ограниченной
истории действий (512 записей), 128KiB для реестра учёта, плюс 128KiB на
каждое нетерминальное задание. Проверяется стоимость заголовка без audit
+32MiB+128KiB+128KiB*active <= hard limit;
фактический audit отдельно должен помещаться в 32MiB. При завершении задания
резерв освобождается. Ошибки приводятся к ограниченному UTF-8 представлению.
Это защищает отказ/отмену/восстановление и рост аудита при удалении данных.
Старые заголовки без достаточного запаса должны отказать при миграции атомарно.

Сохраняемая политика переносится с backup в новый проект; счётчик не берётся
на веру из backup. При запуске и миграции хранилище потоково пересчитывает все
документы. Под блокировкой проекта и CAS обычная запись сверяет полный набор
ключей и версий записей с реестром, его сумму — со счётчиком. Для заменяемых
и удаляемых записей стоимость дополнительно сверяется с фактическим содержимым.
Нетронутые документы при обычном сохранении не читаются. Реестр содержит
вложенные kind→id→(version,cost), максимум120 записей, 64KiB сериализованного
JSON и ограниченную структурную стоимость. Неизвестные виды, некорректные
версии, поля и арифметика дают отказ. Изменение администратором учитываемого
объёма содержимого без повышения версии обнаруживается при полном пересчёте;
такое SQL-редактирование не входит в контракт управляемых writers.
При включённом лимите рост сверх allowance
отвергается; нерастущий payload разрешён и при уже превышенном лимите.
Пачка транзакционна целиком. Старый бинарник отказывается от schema v6 до записи.
Изменение политики доступно владельцу; автоматического удаления нет.

Копию проекта можно скачать и при превышении. Восстановление JSON в новый
проект сохраняет включённую политику и отказывается, если содержимое уже
превышает её лимит; политика не выключается молча. Полное восстановление
PostgreSQL возвращает сохранённые политику и учёт, в том числе overlimit,
после чего разрешены чтение, завершение заданий и освобождение места.

При превышении во время публикации результат и Completed откатываются вместе;
отдельная штатная запись Failed использует запас заголовка. Права проверяются
повторно существующим механизмом. Отзыв прав не расходует payload allowance.

Приёмка: независимый расчёт метрики; limit−1/exact/+1; замена/удаление;
конкуренция/CAS и полный rollback Batch; все namespaces terminal/recovery;
максимальные ошибки/аудит на границе; populated v5 migration/repeat/refusal;
old binary no-write; restart/backup/restore; независимый review и CI.
До прохождения этих проверок функция не объявляется общей квотой проекта.
