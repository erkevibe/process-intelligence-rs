## Найденные ошибки

Неудачные новые базы, конфигурации и потоки сохранены; повтор на той же изменённой базе запрещён. Найдены и отдельно проверены ошибки наследования stdout/stderr, преждевременного чтения незавершённых потоков, FIFO protocol cycle и слишком раннего наблюдения backend. Первый stock-клиент не сохранил полноценный отрицательный HTTP-ответ; второй stock-сценарий выявил допустимое изменение sequence log_cnt, которое первоначальный строгий эталон отвергал.

Первый full Apply реально завершил удаление, но общий сценарий FAILED из-за слишком ранних пяти наблюдений backend. После причинной регрессии новый Apply выполнен на новой базе. Этот исход не переписан в PASS.

Первый migration-сценарий FAILED до проверяемого отказа EXE: сборщик пытался преобразовать sequence в composite JSON. Оригинал сохранён. На новом стенде старый сборщик воспроизвёл ошибку, новый дал два одинаковых полных снимка и совпал с прямым scalar-read. Только затем новый migration-прогон завершился успешно.

Эталон аудита усилен до запуска: repository и deletion projections выводятся из полного PRE, а не просто копируются из фактического baseline export. Одиннадцать регрессий проверяют неверный порядок, policy, время, версию, потерю чужих данных и ошибочные исходные projections.
