# Sprint24: восстановление текущей базы с компактными отчётами

Локально принят полный путь: логическая копия текущей смешанной базы → новая
база → тот же бинарник 0.8.2 → новый вход владельца → проверка сохранённых
результатов. Предыдущие опыты подтверждали перезапуск существующей базы и
восстановление копии до появления компактных отчётов; это отдельный сценарий.

Точные CI и проверка скачанного кандидата фиксируются в PR для его коммита.
Сохранённые локальные акты отражают состояние до этих внешних проверок.
Слияние, тег и готовность всего enterprise-решения не объявляются.

## Фактический результат

| Проверка | Результат |
|---|---|
| Источник | `pi_s23_compat01`, один владелец, два проекта |
| Цель | Новая `pi_s24_compact_dr01` в том же PostgreSQL 18 |
| Бинарник | Прежний 0.8.2, SHA256 `072FB7B8…` |
| Полная логическая копия | Custom-format, 174 424 байта, SHA256 `43E7D920…` |
| Восстановление | `pg_restore --single-transaction --exit-on-error`, код 0 |
| До запуска приложения | Совпали все пять таблиц, схема, ключи, версии, строки, миграции и последовательность |
| Источник | Снимки до копии, после копии и в конце совпали; приложение на источнике не запускалось |
| Новый вход | Новая сессия владельца; доступны два проекта |
| Сохранённые задания | `job-1` — обычный отчёт; `job-3`/`job-5` — компактные прямой и обратный |
| HTTP | 13 сохранённых запросов, три полных набора метаданных и шесть файлов результата/отчёта |
| Содержимое | Полный независимый аудит 90 000 событий и обратного преобразования; прежний пример — 2 события |
| Процессы | 28 принадлежащих сценарию вызовов программ, 56 полных потоков; хеши и длины проверены независимо |
| Завершение | `pg_ctl` и PostgreSQL — код 0, PID-файл отсутствует, тестовые порты свободны |

Проверены уже сохранённые преобразования. Новый конвертер, Java и повторное
преобразование 90 000 событий не запускались. Время алгоритма и память
в этом опыте не измерялись.

SQL-снимок использует полный набор строк и SHA256
`jsonb_send(to_jsonb(row))` вместе с длиной, ключом и версией. Определения
столбцов, ограничений, индексов, владельцы и состояние последовательности
сравниваются отдельно. Перед чтением отвергаются неожиданные публичные
таблицы/представления/последовательности, RLS и пользовательские триггеры.
Кодирование закреплено за тем же PostgreSQL 18.

После входа совпали бизнес-данные и содержимое auth без сессий. Сессионные
изменения и версия auth учитываются отдельно; полное равенство всей базы
после входа не утверждается. Сохранённый исходник защищён полным отпечатком
строки и исходными SHA256/длиной; HTTP скачивает результат и отчёт.

## Сбои и исправление допуска

Первый запуск отказал до рабочего процесса и PostgreSQL: 19 рабочих папок
команд имели завершающий разделитель и не совпали со строгим контрактом.
Сохранены два вызова программ и четыре полных потока.

Вторая попытка дошла до читающего снимка источника. Хеш команды `pg_dump`
был ошибочно переписан как 62 шестнадцатеричных символа; сам файл не менялся.
Защита отвергла команду до создания её процесса. Архив и новая база не
создавались. Сохранены 10 вызовов и 20 полных потоков; PostgreSQL завершён
защитной остановкой с кодом 137.

Исправление проверяет все параметры команд и реальные хеши восьми программ
до любого запуска PostgreSQL. Фактические регрессии отвергли старый короткий
хеш и неверный хеш правильной длины; корректный вариант прошёл. Неверные PID
и отпечаток PID-файла также отвергнуты. Проверки выполняются до производителя.

Третья попытка использовала штатный запуск известного остановленного
PostgreSQL с проверенными PID, временем создания, полными журналами и
отсутствием действующего процесса. PID-файл и WAL вручную не удалялись.
Обычное восстановление WAL дошло до готовности; полный снимок источника
совпал с сохранённым снимком второй попытки **до создания копии**.

Приложение на цели намеренно остановлено с кодом 137. Соответствующий разрыв
клиентского соединения в журнале PostgreSQL ожидаем. Готовность PostgreSQL
проверена последовательностью `1, 1, 1, 0`; затем выполнена чистая остановка.
Журнал postmaster покрывает внутренние процессы PostgreSQL; отдельные native
дескрипторы каждого внутреннего работника не собирались. Прежние неудачи
и исторические UNKNOWN остаются неудачами и UNKNOWN.

## Поставка и границы

В [публичных свидетельствах](../evidence/sprint24/dr-current/summary.json)
сохранены локальные итоги, независимые акты QA/TechnicalDebt/Customer,
HTTP-наблюдения, аудит содержимого и безопасный журнал PostgreSQL.
Manifest различает исходные и опубликованные хеши при замене домашнего пути.
Архив базы, пароли, cookie, auth-снимки и большие скачанные файлы остаются
закрытыми. Публичная сверка manifest проверяет опубликованные байты;
она не повторяет приватный SQL/HTTP-опыт.

Предел архива 128 МиБ проверяется после завершения записи и не является
жёсткой файловой квотой производителя. Для фиксированного опыта выделен
резерв 640 МиБ при неизменных общих ограничениях, свободном месте,
25-секундном измерении и обязательном запасе. Новая RAM-квота не заявляется.

Это копия одной базы с заранее существующими ролями одного кластера.
Не проверены PITR, физическая копия, отказ питания, переход между основными
версиями, HA, RTO/RPO и восстановление ролей viewer/editor или незавершённых
заданий. Браузер/Datastar в этом опыте заново не проверялся.

Следующий отдельный этап — [атомарная квота проекта](ENTERPRISE_QUOTA_PLAN.md).
Документ задаёт план и критерии; ограничение ещё не реализовано.
