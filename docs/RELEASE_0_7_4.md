# 0.7.4 — проверка импорта и сохранности BPMN

Повторный импорт и проверка после перезапуска завершены на неизменном кандидате. Публикация готовится; до итогового решения и публичной квитанции этот документ не подтверждает завершённую поставку.

## Что изменилось

Перед подтверждением XES приложение показывает ключи, типы и количество дополнительных атрибутов, которые не попадут в анализ. Значения этих полей не раскрываются. После подтверждения сохраняются полный исходный XES и история применённых правил. Отчёт о потерях в предпросмотре временный: это не долговечный аудит всех метаданных. Вложенные атрибуты и другие неподдержанные входы по-прежнему отклоняются.

BPMN сохраняет импортированные размеры фигур и использует их при отображении и редактировании положения. Проверенный сценарий: импорт → изменение подписи и координат → сохранение → настоящий XML-экспорт → повторный импорт через браузер → перезапуск → чтение обеих моделей. Полная внутренняя модель, включая граф, подписи, координаты, размеры и точки переходов, сохранилась. Экспорт проверен отдельным HTTP-запросом; событие скачивания браузером не заявляется.

Проверены также настоящий предпросмотр XES, согласие перед импортом, выбор трассы Datastar и история импорта. После перезапуска прежняя браузерная сессия сохранила доступ. Шесть ресурсов — исходный XES, история, JSON обеих моделей и оба BPMN — побайтно совпали с состоянием до перезапуска.

Это конечный проверенный сценарий. Расширенные BPMN-конструкции, изменение размеров пользователем, полная совместимость с Apromore и enterprise-готовность не заявляются. Новый бинарник читает прежние модели без размеров; старый бинарник может отказаться читать новые модели с этим полем. Не выполняйте обратный откат поверх данных новой версии.

## Новая установка

Скачайте Windows ZIP из [релиза v0.7.4](https://github.com/erkevibe/process-intelligence-rs/releases/tag/v0.7.4), когда он будет опубликован. Проверьте SHA256 и распакуйте в новую папку. Существующие установки и их `.local` сохраняйте отдельно. Rust и Java для запуска пакета не нужны; PostgreSQL18.6 включён. Нужен PowerShell7.

В папке распакованного пакета выполните:

```powershell
pwsh -NoProfile -File .\Start.ps1 -Port 3106 -PostgresPort 5486
```

Откройте `http://127.0.0.1:3106/` и создайте первую локальную учётную запись. Пароль — 12–256 UTF-8 bytes. Если порт занят, выберите свободный; не завершайте неизвестные процессы. Данные и секреты хранятся в защищённой `.local` этой установки. Остановка приложения — Ctrl+C; PostgreSQL может продолжать работать. Для резервирования и восстановления следуйте [STORAGE_V2.md](STORAGE_V2.md), используя PowerShell7. Проверки этого выпуска не подтверждают весь путь под Windows PowerShell5.1.

## Сравнение с Apromore и следующие этапы

Из Sprint16 сохраняется конечный эталон полного исходного класса `EventLogServiceImpl` с настоящими зависимостями: 20 основных и два дополнительных примера. Исполняется выбранный private `importFromStream`, а не public транзакционный `importLog` с аутентификацией и сохранением сервиса. Две неверные ручные гипотезы и явные расхождения сохранены; полного паритета нет.

Настоящий Java SplitMiner исполнен отдельно на восьми примерах: семь графов и оригинальных BPMN-экспортов, один `NoSuchElementException` для пустого журнала. Внутренние ERROR-сообщения сохранены. Это конечный reference, а не перенос SplitMiner в Rust, измерение качества или проверка XSD. Alpha+++ из Rust4PM остаётся отдельно обозначенным алгоритмом.

Следующие работы: оставшаяся семантика сервиса Apromore, расширение конечного BPMN-контракта, метрики discovery, фильтры и календарные преобразования. Принятое ранее R3 сохраняется только в своей неизменной области. См. [роадмап](ROADMAP.md), [отчёт Sprint16](SPRINT_16_REPORT.md) и [завершение Sprint17](SPRINT_17_REPORT.md).
