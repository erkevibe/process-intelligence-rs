# Уточнение отрицательной проверки identity

Все пять участников Совета приняли узкое уточнение плана Sprint14. Оно не меняет срок, бюджет, производственные SQL и лимиты 5/2/10 секунд.

Фактический исходный результат сохраняется: стандартная `pi_app` на новом PostgreSQL18.6 успешно читает `pg_control_system()`. Первый прогон C13 завершился неудачно из-за неверного предположения о правах; его нельзя переименовать в успешный.

Для отдельной отрицательной проверки разрешён только один заранее названный искусственный стенд: новая база `pi_restore_s14_identity_source01` и новая проверочная копия `pi_restore_s14_identity_restore01`. В первой базе допускается единственное изменение прав:

```sql
REVOKE EXECUTE ON FUNCTION pg_catalog.pg_control_system() FROM PUBLIC;
```

Это проверка поведения при намеренно запрещённом администратором чтении identity. Она не устанавливает новое требование к штатной роли приложения и не меняет права рабочих установок. GRANT и восстановление ACL не выполняются; стенд остаётся выключенным после проверки.

До изменения прав должны быть получены равные полные снимки новых баз, успешное чтение identity стандартной ролью и действительный план Verify администратора. После изменения требуются успешное чтение той же identity администратором, настоящий отказ42501 у ограниченной роли, затем отказы Verify и Apply действительного старого плана без изменений данных и без создания результата очистки.

Проверяются все ACL системных объектов и ролей, включая различие между NULL и эффективными правами по умолчанию. Единственная разрешённая разница — удалённое PUBLIC EXECUTE указанной функции в новой исходной базе. Между подготовленным ограниченным состоянием и завершением проверок ACL, полные данные и каталоги обеих баз должны совпадать. Нужны полные потоки и коды завершения, штатная остановка PostgreSQL, закрывающий бюджет и независимая проверка QA/TD.

Принятие этого уточнения само по себе не является результатом теста: исходники и точная конфигурация нового прогона ещё требуют отдельной проверки до запуска.
