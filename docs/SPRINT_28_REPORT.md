# Sprint28: сохраняемое построение BPMN

Реализация: [PR №41](https://github.com/erkevibe/process-intelligence-rs/pull/41).
Выбранная в Sprint27 эвристика `structured_variants_v1` теперь работает в
Rust-сервере через сохраняемые задания. Это собственный ограниченный метод,
не полный Inductive Miner и не порт SplitMiner. Java и Python серверу не нужны.

## Пользовательский сценарий

В действиях сохранённого журнала можно построить BPMN. До подтверждения приёма
сохраняются точные варианты и версия источника. Модель, происхождение обучения
и завершённое задание публикуются одной транзакцией. Повтор запроса не создаёт
вторую модель. Построение и оценка используют общие два места операций и один
вычислитель.

Отмена, отзыв прав и изменение источника проверяются до публикации. Первое
построение отказывает при устаревшем источнике; явный повтор использует
сохранённый исторический снимок. Незавершённые задания после восстановления
получают `interrupted`; повтор всегда явный. Удаление задания сохраняет
часовую квитанцию для распознавания повторного запроса.

Результат показывает оценку **на обучении** и предлагает явно выбрать
контрольный журнал. Точный обучающий снимок, изменённый источник и другой
журнал с теми же вариантами имеют разные подписи. Другой журнал сам по себе
не доказывает независимость данных. Редактирование модели снимает точную
привязку обучения; обычный BPMN-импорт её не выдумывает.

## Сохранность и обновление

Схема v5 вводится явной офлайн-миграцией v4 → v5. Прежние контрольные суммы
миграций сохранены. Старое приложение 0.9 отказывает открывать v5 до записи.
Восстановление резервной копии повторяет построение и вычисления под общими
ограничениями и отвергает согласованную подделку численного результата.

Изменение собственной версии package с 0.9 на 0.10 сохраняет прежний отпечаток
метода оценки: нормализуется только эта строка версии, остальные зависимости
и вычислительные исходники продолжают участвовать в проверке. Настоящий отчёт
из 0.9 подтверждён новым бинарником.

Диагностика v5: [capacity-diagnostic.sql](../tools/sprint28/capacity-diagnostic.sql).
Она учитывает восемь видов записей и работает в read-only repeatable-read
транзакции. Это наблюдение потребления места, а не квота или сертификат схемы.
Инструкция обновления — [DATABASE_RECOVERY.md](DATABASE_RECOVERY.md).

  отзыв прав, восстановление, сохранность завершённого результата и полный backup replay.
- Заполненная v4 обновлена без изменения записей, ревизий, sequence и прежнего

## Границы

Не более 6 действий, 64 трасс, 500 событий, 32 вариантов, 64 событий в трассе,
64 узлов и 128 переходов модели. До 8 сохранённых построений и 64 моделей
на проект. Действует 30-секундная кооперативная граница вычисления.
Пустой журнал даёт `no_data`, неподдерживаемый вход — явный отказ.

На фиксированном примере повторной метки precision 0.5 остаётся в эксперименте
Sprint27. Высокая оценка на обучении не гарантирует качество новых данных.
Общая дисковая квота проекта, Linux/TLS-внедрение, OIDC, несколько экземпляров
и HA этим инкрементом не закрываются. Следующая очередь — P3.

Слияние допускается только после двух успешных CI окончательного коммита;
актуальный статус виден в PR №41. Отдельный тег или релизный бинарник не создан.
