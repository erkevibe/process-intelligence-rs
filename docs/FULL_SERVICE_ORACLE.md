# Сравнение полного класса импорта Apromore

Эта проверка отлична от исторического извлечённого метода Sprint07. Исходный класс целиком собирается Gradle вместе с настоящими зависимостями. Наблюдатель использует reflection только для вызова оригинального приватного `importFromStream`; тело метода и остальные исходники не меняются. Публичная транзакционная операция `importLog` не исполняется.

Пины: ApromoreCore `bbf24dfd43e72d6992392465f875a4367cbe792b`, SupportLibs `99887cddb0d88a107c3005f6711c1ffa67dd13e1`, Gradle 7.1.1, Temurin JDK 11.0.32.1+1. Идентичность исходников проверяется по полному Git tree и каждому Git blob; скачанный ZIP сам по себе не считается доказательством исходного кода. Два BAT-файла в GitHub ZIP отличаются концами строк: вместо их исправления получены точные исходные Git-байты из закреплённого commit.

## Корпус и результат

Основной манифест: `fixtures/oracle-full-service/corpus.json`, SHA256 `3af07e2094abd0a91cb6bbbe0e152dc9341ca40e75c3b238b6db1ec0b30abf60`. Он фиксирует 20 входов, расширения, ручные гипотезы и ожидаемые поля. Дополнительный манифест фиксирует два отдельных случая коллекций. Основные ожидания после исполнения не переписывались.

Java выдаёт атрибуты с типами и вложениями, классификаторы, расширения, глобальные атрибуты, порядок трасс и событий, исключения, фактическую фабрику и чтения потока. В Java timestamp имеет миллисекундную точность; Rust способен сохранять более точный момент. Это различие явно обозначено. Исходные позиции в отчёте Rust проверяются против его исходного события, а не приписываются Java-сервису.

`tools/oracle/compare-full-service.mjs` сверяет входы, исходный класс, реальные наблюдения Java и результат Rust. Сравниваются типы и значения метаданных, порядок классификаторов и событий, имена, lifecycle и моменты времени. Счётчик событий не заменяет такое сравнение. Явные расхождения и две опровергнутые гипотезы сохраняются в результате. Завершение наблюдения всех входов не означает прохождения всех гипотез или равенства сервисов.

## Воспроизведение и границы инструментов

Подготовка и исполнение этого спринта представлены `tools/oracle/full-service-*`: загрузка закреплённых входов, внешний Gradle init, полный build proof, Java-наблюдатель, ограниченный Windows Job и полные потоки с реальными exit codes. Сценарии исполнения привязаны к каталогу, ресурсному бюджету и дедлайну Sprint16; это диагностические инструменты, не универсальный установщик. Для нового запуска после дедлайна нужен новый проверенный профиль исполнения. Нельзя снимать ограничения молча.

Чистые проверки, пригодные для CI:

```sh
node tests/full_service_comparator.mjs
mkdir -p .local/sprint16/service
python3 tools/oracle/full-service-bootstrap-tests.py
```

На уже подготовленных частных наблюдениях сравнение запускается так:

```sh
node tools/oracle/compare-full-service.mjs OBSERVER_EXE fixtures/oracle-full-service JAVA_OBSERVER_DIRECTORY NEW_OUTPUT_DIRECTORY
```

`OBSERVER_EXE` собирается из `examples/full_service_observer.rs`; принимает только явный `--trusted-corpus` и не является HTTP API. Это диагностическая двойная наблюдаемость Rust4PM и продуктового строгого допуска. Исходники, JAR, кеши зависимостей и полные журналы upstream не входят в публичный Rust ZIP. Лицензии upstream сохраняются в частной сборке; самостоятельный Rust-продукт не выдаётся за официальный Apromore.
