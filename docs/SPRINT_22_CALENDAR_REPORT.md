# Sprint22: пояснения календарных отказов R5

После основной поставки [PR25](https://github.com/erkevibe/process-intelligence-rs/pull/25) выполнен небольшой следующий этап того же восьмичасового спринта. Основной результат не переписывается: прогон 90 000 событий завершился отказом `report_byte_limit`, а не успешным преобразованием.

## Изменение продукта

В таблице рабочей длительности появились два пояснения:

- `calendar_timezone`: неизвестное имя зоны либо несовместимость именованной зоны с фиксированным смещением; предложено исправить имя/смещение.
- `calendar_boundary`: переход местного времени, на котором расчёт невозможен; предложено изменить рабочие часы или зону.

При отказе остаётся прочерк. Расчёты, коды и структура API, экспорт, хранение и фильтры не менялись. Неизвестная причина по-прежнему получает безопасное общее сообщение; названия трасс экранируются.

## Локальная приёмка CALUX-01–05

| Проверка | Фактический результат |
|---|---|
| Ошибки зоны и конфликт смещения | Настоящие ошибки движка переданы в renderer-тест; HTTP 422 отклоняет изменение до сохранения |
| Весенний пропуск и осеннее повторение часа | Реальные отказы для Europe/Berlin, воскресенье 02:30–04:00; подсказка и прочерк видны после перезагрузки |
| Исправление часов на 01:00–04:00 | Заранее рассчитанные 7 200 000 / 14 400 000 мс, в интерфейсе 2 / 4 часа |
| Совместимость C01/C02 | 60 исходных HTTP-ответов независимо проверены; настройки и рабочие длительности совпали |
| Сохранность после ошибочного ввода | Неизвестная зона и конфликт смещения дали 422; прежние настройки и результат сохранились |
| Регрессии | Три новых renderer-теста и пять существующих календарных тестов прошли; сохранены ручные временные примеры Sprint08 |
| Браузер | Настоящие отправки формы, переходы и перезагрузки; статусы 422 прочитаны из событий браузера без сохранения заголовков |
| PostgreSQL | После аварийного завершения предыдущей проверки выполнил штатное восстановление WAL; затем остановлен нормально, PID-файл удалён самим PostgreSQL |

Root выполнил браузерные действия; QA и Customer независимо просмотрели сохранённые свидетельства. TD проверил технические результаты и восстановление. Локальная приёмка не подменяет проверки публикации точного коммита.

## Воспроизводимые свидетельства

Пакет [evidence/sprint22-calendar](../evidence/sprint22-calendar/manifest.json) содержит исходные ответы HTTP, синтетические CSV, снимки и состояния браузера, два точных stdout тестов, реальные решения независимых ролей и протокол предварительного согласования. [Проверяющий пакета](../tools/sprint22-calendar/README.md) также исполняет отдельный проверяющий HTTP-ответов.

Сводка 35 процессов и 70 потоков вывода пяти фаз (`build01`, `build02`, `live01`, `live02`, `audit02`) — явно обозначенная проекция метаданных. Два stdout опубликованы полностью; остальные 68 исходных потоков остаются в частных материалах и были независимо проверены QA/TD. Публичные хеши этих потоков не означают возможность перечитать их содержимое из пакета. Последующие проверки поставки учитываются отдельно.

Неудачные попытки сохранены: трёхминутный тайм-аут компиляции, неверное ожидание имени трассы в проверяющем CSV и ошибка видимости вспомогательной функции до запуска Python. Результаты этих попыток не засчитаны как успешные; новых UNKNOWN нет. Шесть исторических UNKNOWN не исправлялись задним числом.

## Что остаётся

Этот этап закрывает только CALUX-01–05. Ошибочные календарные формы пока показывают прежнюю страницу с JSON-ошибкой; новый текст `calendar_timezone` в таблице проверен через настоящую ошибку движка, без создания недопустимой сохранённой строки в браузере. Календарная форма использует обычный POST и переход; SSE/Datastar для неё не заявляется.

Для R5 остаются большие отчёты, готовность окончательной квитанции захвата после завершения процесса, общие квоты хранения, работа нескольких экземпляров и дальнейшая эксплуатационная приёмка. Полное закрытие R5 и готовность enterprise не заявлены.

Кандидат основан на `8a5732224fdc20e0094e689cf75b0818a335e6fa`. Бинарники для локального сравнения: C01 `4121BD68…D1525`, C02 `13A43541…9F32C`; полные хеши находятся в манифесте. Релиз, тег и слияние этим этапом не создаются. До признания публичной поставки нужны CI точного коммита и два независимых скачивания исходников с исполнением проверяющего из скачанной версии.
