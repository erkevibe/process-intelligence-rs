## Приоритет и проверяемый результат

1. Восстановить штатную сборку полного неизменённого `EventLogServiceImpl` закреплённого ApromoreCore `bbf24dfd43e72d6992392465f875a4367cbe792b` с настоящими зависимостями. Gradle7.1.1 и JDK11 закрепляются; полный source tree, jars, classes, параметры и фактические native exits/потоки сохраняются. Прежний неудачный single-file javac probe не повторяется без устранения причины.
2. Зафиксировать новый корпус до исполнения и сравнить поля, порядок, defaults, classifiers, typed attributes, lifecycle, timestamp precision/offset и отказы. Вызывать настоящий выбранный import path. Reflection private `importFromStream` полного исходного класса обозначается отдельно от public `importLog` с пользователем, авторизацией и persistence; отсутствующее исполнение не домысливается. Извлечённые методы и заглушки не закрывают этот этап.
3. Исправлять доказанные действующие расхождения Rust либо явно показывать потери поддержанного представления в preview/JSON/UI. Исходный файл сохраняется. Прежняя история импорта и policy не меняют смысл без версии и проверки совместимости. Supported subset не объявляется полным R2 parity.
4. После связного R2 результата либо конкретно воспроизведённого и описанного dependency blocker — BPMN/R4 и выбранные R5. Начальный конечный BPMN contract: start/end/task/exclusive/parallel, sequence flows, labels, node XY и waypoints; strict roundtrip и negative cases. Начальные conversion pairs: XES↔CSV и strict BPMN↔model, с отдельным loss report. Изменение supported contract объявляется до реализации. Качество требует реального miner и независимой методики; Alpha+++/DFG/variants не переименовываются в Split Miner.
5. Один интегрированный кандидат, независимые QA/TD, точный CI и проверяемая публичная поставка. Для принятого изменения runtime нужен новый неизменный пакет; одних документов для него недостаточно. Старые принятые R3/R2 доказательства переносятся только при подтверждённой идентичности действующих путей.

## Ресурсы и управление риском

Только новый `.local/sprint16`:8GiB логических и выделенных байт; свободно не менее8GiB. Внутри: service/reference до4GiB, Root build/integration до3GiB, QA/metadata/public reserve1GiB. Source ZIP и распакованное дерево — по128MiB максимум. Изолированные Gradle home/cache/temp, не более двух workers и1GiB heap, без daemon. Старые JDK/source/deps читаются без записи; старые установки, БД и доказательства не изменяются. Удаление и дополнительное сжатие не входят в спринт.

Риск средний для изолированных черновиков; допуск к потере пользовательских данных и ложной приёмке низкий. Для черновиков облегчённый рабочий цикл, полный контур FLW — для интегрированного кандидата. Не нужен повтор общего native inventory старого S14 ради отдельной Java-сборки. Перед тяжёлой работой проверяются собственные пути/идентичности, бюджет, deadline, полный ограниченный stdout/stderr и настоящий exit. При общей повторной причине исправляется механизм, а не переименовывается прогон.
