## Измерения

На AMD Ryzen AI 9 HX 370, 12 cores / 24 threads, Windows 11 Home 10.0.26200 x64, точный clean release: 10 000 событий, 1 000 трасс, 20 действий; parse+analysis 25 мс, HTTP upload wall 31,70 мс. Цель до 5 секунд достигнута в этой области измерения. Это не сравнение производительности с Apromore.

Process-lifetime peak working set: 109 658 112 bytes, около 104,6 MiB, включая предыдущие большие входы. Точный RSS отдельной задачи и цель 512 MiB остаются unverified: измерена working set всего процесса, а не per-job RSS. Общий потолок памяти этими числами не доказан. AC11 допускает такое явное ограничение измерения.

## Что исправлено и что остаётся

Исправлены фактически обнаруженные проблемы: запуск Windows HTTP harness через прямой LLD; пустые XES traces в адаптере; Origin обычной загрузки; whole-body ответ 413; устаревшие job/panel ответы; ограничение буферизации двух uploads; изменение raw vendor bytes при Git checkout. Для исправлений есть независимые регрессии. Прежние неуспешные попытки и исправления проверяющих инструментов не выданы за успешные прогоны.

Сырые журналы, HTTP-ответы и временные файлы остаются приватными в `.local`; опубликованы безопасные агрегаты и хеши. Покрытие журналов имеет ограничения: raw Linux CI, полный поток агентов и часть ранних выводов отсутствуют или неполны. Карточки задач консолидированы ретроспективно с явной пометкой. Формулировка «все процессы без ошибок» не применяется.

R1 хранит последние восемь журналов в памяти, теряет данные и историю задач при перезапуске, слушает loopback. Отмена ожидает безопасной границы непрерываемой фазы стороннего парсера. UI показывает первые 200 событий выбранной трассы, JSON — все. Minor Customer UX findings приняты для следующей полировки. Enterprise readiness и AC15 legacy compatibility не подтверждены.
