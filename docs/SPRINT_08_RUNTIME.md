# Контракт приложения 0.6: кандидат Sprint08

Это описание реализуемого кандидата, не отчёт о независимой приёмке. Полные условия R2–R5 сохраняются в [матрице](SPRINT_08_SCOPE.md). Старые приложения и их базы не обновляются автоматически.

## Подтверждённый импорт XES

Строгий импорт остаётся прежним. Отдельная страница «XES с предварительным просмотром» применяет именованную политику `apromore_validate_log_v1`: показывает исходное и предлагаемое число трасс/событий, исходные индексы, добавление отсутствующего lifecycle и удаление неподдержанных событий/пустых трасс. Она не запускает полный оригинальный Apromore service.

До подтверждения проект не меняется. Для подтверждения требуется явное согласие. Новый журнал сохраняет точный UTF-8 исходник, SHA256, UUID операции, исходные actor/project, UTC-время, политику и полный список действий. Исходник находится в неизменяемой записи `log_source`, а не в изменяемой записи настроек. Страницы журналов предоставляют скачивание оригинала и истории импорта. Старые журналы, у которых сохранён только SHA256, не получают выдуманный оригинал: сервер отвечает `original_unavailable`/`history_unavailable`.

Лимиты: 20 MiB, 100000 событий, 20000 трасс и не более 200000 действий политики. Допустимый по размеру файл может быть отклонён по числу действий; лимиты не являются общим пределом RAM. HTML показывает до 200 действий, JSON — полный принятый отчёт. Полностью удалённый результат подтвердить нельзя.

Одновременно хранится до двух исходников preview на платформу, до 64 статусов завершённых/неопределённых операций. Preview привязан к пользователю и проекту, действует пять минут; очистка просроченного происходит при следующем создании preview. Готовый просмотр можно отменить. После начала подтверждения отмена возвращает отказ и не означает отмену записи. Повтор успешного подтверждения того же токена открывает тот же журнал, пока сохранён статус. Перезапуск удаляет неподтверждённые просмотры.

При неопределённом результате записи БД повторное подтверждение этого токена запрещено. Перезапустите приложение и проверьте список журналов/историю по UUID операции, прежде чем загружать файл снова. Автоматическая дедупликация повторной загрузки после перезапуска и транзакционная задача подтверждения не реализованы. Отмена обычных долговечных jobs сохраняет свой прежний контракт.

## Проекты, папки и права

Папки принадлежат одному проекту. До 128 папок; имя после trim содержит 1–200 UTF-8 bytes и уникально среди соседей с учётом регистра. Идентификатор папки — постоянный канонический UUIDv4. Перемещение папки не меняет идентификаторы журналов/моделей. Циклы, отсутствующие родители, чужие ресурсы, некорректные ссылки и удаление непустой папки отклоняются. Удалить можно только пустую папку; удаление проекта и перенос ресурсов между проектами не поддерживаются.

Изменение папок использует ревизию проекта и CAS: устаревшая форма получает конфликт, не перезаписывает новую версию. Viewer видит папки и ресурсы; editor/owner меняют структуру. Только owner переименовывает, архивирует и восстанавливает проект. Архивирование сохраняет данные и закрывает доступ к проекту до восстановления. Для архивирования текущего проекта должен существовать другой доступный активный проект. Сессии переключаются туда, где это возможно.

Перед фактической публикацией сервер повторно проверяет текущую сессию, роль и активность проекта под общей блокировкой авторизации, удерживаемой до записи. Архивирование/изменение прав сериализуются с публикацией. Ранее начатая операция либо записывается до архивирования, либо получает отказ. Сохранение личного представления отдельно допускает viewer, не разрешая запись ресурсов. Это локальная последовательность одной платформы, не распределённая транзакция нескольких серверов.

## История действий и восстановление

Успешное изменение ресурсов и запись его истории выполняются в одной транзакции PostgreSQL. Запись включает последовательный номер, UTC, actor/project, действие, ресурсы и ревизию. Отказы не объявляются успешными операциями. Для проекта удерживаются последние 512 записей изменений репозитория и отдельно последние 512 административных событий этого проекта; total/dropped явно доступны. Другой проект не вытесняет эту историю. Административная история доступна owner. Страница показывает до 200 записей, экспорт — все удерживаемые.

Это ограниченная эксплуатационная история, не неизменяемый внешний журнал для юридического аудита. Привязка исходного файла и действий проверяется повторным вычислением SHA256 и политики; она не удостоверяет внешнюю личность исторического actor. При восстановлении в новый проект исходная история сохраняет исторические идентификаторы, а новые действия получают новый project ID. Административная история находится в auth-документе БД и включается в полную резервную копию PostgreSQL; встроенная копия одного проекта не экспортирует учётные данные, сессии и административный auth-документ.

Schema PostgreSQL остаётся 2. Старые обычные EventLog и метаданные без новых полей читаются. Подтверждённые импорты записывают версионированный envelope `log_source`; папки/история добавляют поля метаданных. Старый бинарный файл не обещает читать эти новые данные: downgrade не поддерживается. Перед сменой версии используйте полную резервную копию и восстановление в новую базу, не прежнюю пользовательскую установку. Проверенный инструментальный путь backup/restore/offline migration требует PowerShell7.6.5; полный путь Windows PowerShell5.1 остаётся UNVERIFIED.

## Календарь и discovery

Календарь принимает фиксированное UTC-смещение либо именованную IANA-зону (`chrono-tz =0.10.4`, tzdb2025b). При named zone фиксированное смещение должно быть нулевым. Интервал UTC полуоткрытый [start,end); расписание, дни недели и праздники определяются по местной дате. Конец1440 означает следующую местную полночь. Несуществующая или неоднозначная граница расписания возвращает отказ; переход через полночь не поддерживается. Максимальный диапазон — 3660 календарных дат. Отсутствующие timestamps не превращаются в вычисленную длительность. Legacy Calendar и lifecycle start/complete pairing этим контрактом не покрыты.

Отдельный developer API запускает настоящий Alpha+++ из Rust4PM/process_mining0.6.2 и экспортирует PetriNet/PNML. Его контракт и замороженные примеры — [DISCOVERY_ALPHA.md](DISCOVERY_ALPHA.md). Он не интегрирован в BPMN-редактор, jobs и UI, не является Split Miner и не получает измеренных fitness/precision/simplicity. Исходный наблюдаемый variants baseline в UI сохраняет своё имя и ограничения.

## Обязательная проверка кандидата

Обычные тесты не заменяют PostgreSQL, native browser, повреждённую копию, restart, archive/logout race, неизменность heavy-record versions, вытеснение кеша и холодный запуск точного Windows-пакета. Итоговый отчёт отдельно укажет выполненные проверки, неизменный source/binary/package SHA, сохранённые прежние установки и все открытые критерии.
