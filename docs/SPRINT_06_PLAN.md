# Sprint06 — настоящий XES reference

Начало: 2026-10-11 02:04:15 UTC. Предел: 06:04:15 UTC (четыре часа). Freeze не позднее 04:34:15; последние 90 минут защищены для проверки и доставки. Это следующая итерация, полные R2–R5 и enterprise не объявляются завершёнными.

## Предложение S6-P1

Один фокус: расширить реальное сравнение с закреплённым ApromoreCore до настоящего XES parser и XLog consumer, отделяя исходный порядок от явно выбранной сортировки времени. Риск-аппетит низкий в отношении пользовательских данных, средний для исследовательского oracle. Контроль: реальные независимые Customer/PM/QA/TD, голосование по этому предложению, независимый replay и аудит выбранных процессов. Установки и базы прежних версий не изменяются.

1. До 02:48:15 доказать вызов настоящего OpenXES parser закреплённого upstream и неизменённого LogParser XLog overload хотя бы на одном примере. Заглушки и прежний текстовый адаптер не засчитываются. Закрепить исходники, зависимости, SHA256, лицензии, JDK и параметры. Portal/service импорт отдельно от parser; обещается только реально исполняемый компонент.
2. Зафиксировать до исполнения малый корпус XES с ручными ожидаемыми значениями: исходный и обратный порядок, равные timestamps, эквивалентные offset/UTC, пропущенное/некорректное время, lifecycle start/complete, пустая трасса, Unicode. Сохранить шесть прежних регрессий. Сравнивать реальные доступные case/activity/event/variant/attribute поля отдельно; никакого общего процента совместимости.
3. Реальный reference читает исходный XES, не заранее преобразованный текст. Выдать machine-readable фактические результаты parser и consumer; явно указать classifier/defaults, source order, normalisation, ошибки и каждое расхождение Rust. Timestamp sorting Rust сравнивается с ручным контрактом, если legacy не сортирует; legacy time parity не выдумывается.
4. Независимый QA воспроизводит reference и Rust на неизменённых входах и проверяет отрицательные случаи. ProcessLogAuditor фиксирует exit, raw stdout/stderr, SHA/размеры, captured/missing/truncated и ограниченность покрытия. TD оценивает причины и долг. Исходные upstream классы не меняются, секреты/пользовательские данные не публикуются.
5. Доставить воспроизводимые tools, corpus, результаты, инструкцию и обновлённый роадмап в публичный репозиторий через проверенный PR/CI. Если производственный Rust не требует изменения, Windows0.5 остаётся текущей поставкой: не перепаковывать одинаковый runtime ради номера. Если выявится дефект и заранее определённый контракт требует исправления, отдельный frozen candidate, регрессии и независимая проверка; при нехватке резерва фиксировать дефект открытым.

При провале feasibility gate завершить диагностический corpus/tooling результат, actual XES legacy пометить BLOCKED/UNVERIFIED, не переключаться автоматически на опасную очистку. Это разрешённый ограниченный fallback, а не закрытие R2.

## Приёмка

A01 — закреплённые настоящий parser/consumer/dependencies и одно фактическое исполнение либо честный BLOCKED с причиной.
A02 — неизменённый corpus, ручные expectations до запуска, полные SHA/параметры.
A03 — реальные reference результаты и отдельный Rust replay; все расхождения по полям.
A04 — исходный/временной порядок, ties/offset/missing/lifecycle/некорректные входы явно проверены в доступном контракте.
A05 — независимые QA, аудит выбранных журналов, TD и новые финальные голоса.
A06 — проверенный публичный PR/CI, документация и сохранность прежних поставок.
