# Sprint09: руководство по исправленному кандидату0.7.1

Этот документ описывает замороженный кандидат, а не объявляет выпуск принятым. Итоговые статусы и ссылки на поставку появятся в отчёте после независимых проверок.

## История действий

В истории проекта видны исполнитель, время, действие, ресурс и сохранённая политика. Только событие, атомарно сохранённое вместе с изменением, получает подтверждённый результат. Старые события без политики остаются явно неопределёнными. История из пользовательской копии проекта помечается как непроверенная: импорт не превращает её в подтверждённые события сервера.

Каждый журнал хранит последние512 записей и показывает общее число событий и число вытесненных записей. Экспорт сохраняет этот порядок и счётчики. Свидетельства удаления доступны бывшим владельцам отдельно от уже удалённого проекта.

## Постоянное удаление проекта

Для архивирования текущего проекта нужен другой активный проект с правом записи: роль Owner или Editor. Проект, доступный только для просмотра, не подходит как замена. Затем откройте предпросмотр удаления архивированного проекта, проверьте точный ID и состав удаляемых данных. Для подтверждения нужны ID и фраза `УДАЛИТЬ`. Если права или данные изменились после предпросмотра, получите новый предпросмотр. Незавершённая фоновая работа блокирует удаление.

После подтверждённого удаления проект, его данные и ссылки удалены одной транзакцией; остаётся минимальное свидетельство действия. Для восстановления нужна заранее сохранённая копия. Приложение не утверждает, что копия у вас есть или что она проверена. Резервные копии и PostgreSQL могут продолжать хранить ранее записанные данные: эта операция не является безопасным стиранием носителя.

## Очистка старых копий данных

Это отдельная ручная операция оператора. Она удаляет только сохранённые старые repository-копии после проверки актуальных данных, полного архива и его восстановления в новую базу. Она не удаляет проект и не обещает уменьшить файлы PostgreSQL сразу после завершения.

Используйте штатные инструменты из той же установки. Проверенный полный путь backup/newrestore в этой итерации использует PowerShell7.6.5. Проверка холодного запуска в Windows PowerShell5 не подтверждает работоспособность backup/restore в PowerShell5. PostgreSQL должен соответствовать поставляемой версии18.6. Пользовательские базы и нестандартные схемы не входят в этот конечный набор проверки.

1. Сохраните полный штатный архив базы и исходный файл manifest в приватной папке установки `.local`. Проверьте, что этот архив действительно восстанавливается.
2. Остановите приложения, использующие исходную и контрольную базы. Выберите новое имя контрольной базы `pi_restore_*`; инструмент не восстанавливает поверх существующей базы.
3. Выполните `tools/cleanup-legacy.ps1` в режиме `Preview` с архивом, новым файлом плана, исходной базой и новой контрольной базой. Сохраните выданный SHA256 плана и проверьте число кандидатов.
4. Выполните `Apply` с теми же параметрами и точным `ConfirmPlanSha256`. Изменение архива, плана, данных, прав или идентичности базы приводит к отказу.

Секреты берутся из приватной конфигурации установки. Не вставляйте пароль или URL базы в команды, журналы, отчёты и переписку.

## Аварийный исход

| Результат | Что делать |
|---|---|
| Подтверждённая фиксация | Сохранить receipt и результат; проверить актуальные данные перед запуском приложения. |
| Подтверждённая фиксация, receipt не записан | Изменение базы уже произошло. Сохранить вывод и план; повторное удаление автоматически не запускать. |
| Результат фиксации не подтверждён | Сохранить оригинальный структурированный вывод и план. Инструмент выполняет полное сравнение только для чтения и сообщает `complete_pre`, `complete_post`, `unexpected_state_stop` или `unavailable_stop`. Успешный receipt при этом не создаётся. Исход не угадывать, повтор автоматически не запускать. |
| Неожиданное состояние или сравнение недоступно | Остановиться и исследовать сохранённые доказательства; не угадывать исход по ошибке соединения. |
| Нужен возврат к состоянию до операции | Восстановить оригинальный полный архив ещё в одну новую базу, проверить данные и доступ, затем явно выбрать её для приложения. |

Не восстанавливайте архив поверх исходной базы и не возвращайте старые JSON-копии в работающую нормализованную базу. Старые пакеты, теги и действующие установки не заменяются этой итерацией автоматически.
