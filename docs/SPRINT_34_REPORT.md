## Поставка и сервер

Установлена принятая Linux-поставка PR46, исходник
`c9440ebb328a7922587bffbe5091e31009fb3c5e`; его дерево совпадает с принятым
main `14a75e3e6b7d4758e712784c0f67cf983b72d24f`. Артефакт GitHub Actions
12580418520, ZIP SHA256
`ec789bcb25c19aae04ff0fb5cbca8c8dd5e538aa8953e4b8c6cbd6c7a631fcc9`.
Внутренний tar SHA256
`5e3d79069ad5af60260bc27c148643e353d7704925359dfbfa72fba2b66ebf6e`.
Все 1267 файлов проверены по manifest перед запуском. Это установка
принятого бинарника 0.11.0, а не новая сборка Rust в этом спринте.

Цель: Ubuntu 24.04, x86-64, непривилегированный LXC, 8 CPU, 8 ГиБ RAM,
том ZFS 100 ГиБ, glibc 2.39. PostgreSQL 18.6 установлен из подписанного
репозитория PGDG. База UTF8/C.UTF-8 создана из template0, поскольку исходный
пустой кластер имел SQL_ASCII. Роль приложения без superuser/createdb/createrole.
Схема 6 создана для новой пустой установки; это не миграция чужой рабочей базы.

Приложение и база слушают loopback; Caddy 2.11.7 с проверенным закреплённым
архивом принимает HTTPS на LAN-интерфейсе. UFW разрешает SSH, HTTP/HTTPS и
HTTP3 только из /24 локальной сети, остальные входящие подключения запрещены.
Файловый credential передаётся systemd через LoadCredential. Ограничения
ProtectSystem/ProtectHome/NoNewPrivileges работают в этом LXC без ослабления.
Существующие Postfix, SSH и службы контейнера не заменялись.

Частный CA хранит ключ только на компьютере оператора. Сертификат сервера
содержит SAN с точным IP, действует до 25.10.2027. Клиенты с явно переданным
CA успешно проверяют цепочку и IP; неверный SNI отвергнут, OpenSSL отдельно
подтвердил отказ hostname mismatch. Доверие браузера ещё не принято.
Пароли и ключи исключены из Git; в публичные данные они не проецируются.

## Обслуживание и остаток

Добавлены скрипт и units [ежедневной копии](LINUX_LAN_OPERATIONS.md).
По расписанию 03:00 Asia/Qyzylorda, последние 14 завершённых копий,
согласованная остановка и возврат приложения, защищённые конфигурация/роли,
проверка TOC и streaming SHA256. `.partial` не выдаётся за готовую копию.
При ошибке восстановления службы маркер сохраняется до следующей попытки.
Ручной запуск установленного исходника и отдельное срабатывание таймера
прошли. Сам архив ежедневной копии восстановлен в отдельную базу.
LAN-конфигурация и proxy unit теперь также хранятся в `deploy/linux`;
их точные байты установлены на сервер, Caddy проверен и перезапущен,
новое HTTPS-соединение успешно. Первое штатное ежедневное
время наступит после текущего окна и не заявляется уже наблюдённым.

Открыты: подтверждение доверия CA и физический браузер; выбранное хранилище
для регулярной копии вне сервера; план обновления сертификата; операторский
процесс реакции на ошибки копирования; реальные данные и вопрос пилота P4.
Репетиция восстановления была в том же кластере. Потеря всей машины,
перезагрузка LXC/гипервизора, HA, RPO/RTO и SLA этим не доказаны.

Исходные приватные протоколы: `.local/server-deploy-20261025` и
`/root/process-intelligence-install/acceptance` на целевом сервере.
Тестовые проекты предыдущих попыток архивированы через приложение; сохранены
отдельная демонстрация и пустой рабочий проект. Два тестовых аккаунта имеют
случайные пароли и не имеют членства в рабочем проекте.
