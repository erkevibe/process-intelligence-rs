# Sprint29: наблюдаемый контракт API — первый инкремент P3

[PR №42](https://github.com/erkevibe/process-intelligence-rs/pull/42) фиксирует
поведение HTTP API версии 0.10 и добавляет исполняемый сценарий. Код
приложения и схема хранения не меняются. [Контракт](API_SUPPORT_CONTRACT.md)
описывает доступ, повторы, состояния, ошибки, SSE и экспорт, но не вводит SLA.

## Проверено локально

На отдельном синтетическом стенде прошли 28 проверок и 33 HTTP-запроса:
анонимный redirect, пользователь без членства, owner/viewer, чтение и запреты
записи, no-store, конечный SSE без полного входа, три повтора одного запроса,
409 на изменённую форму, 422 в JSON/HTML и отказ неизвестному полю.

Три настоящие резервные копии имеют HTTP 200, правильную схему, digest и
ожидаемые ресурсы. Их полные байты совпали до и после чтения, повторов и
отказов. Ранее скачанный отчёт сохранил тот же SHA256 после нового процесса.
Смена процесса доказана внешним стендом: PID, creation time, одинаковые байты
проверенного приложения и полные завершённые выводы закреплены отдельно.
Standalone probe сам по себе этого не доказывает.

Закрытый Windows-запуск API05: 8 captures, 16 streams, 97 pins. PostgreSQL
штатно остановлен. Независимая приёмка проверила все 33 ответа, три backup JSON
и связь отчёта с seed-ответом; блокеров нет. Пользовательский сервис не изменён.

Первый прогон выявил неверное ожидание теста: понижение editor до viewer
сохраняет чтение. Тест исправлен пользователем без членства перед grant.
Рецензент также потребовал проверять настоящие backup/digest перед сравнением
байтов; это добавлено. Несколько последующих запусков были остановлены
resource_sample_timeout до старта PostgreSQL и не считаются PASS.

Для освобождения воспроизводимых файлов сохранены и проверены бинарники
принятой сборки; стандартный Cargo clean удалил только её сборочные результаты.
Дубликаты контрольных подделок сохранены в ZIP с проверкой каждого SHA256.
Исходники, база, эталонный пакет, native captures и итоговые proof не удалялись.
Ограничения ресурсов и срок проверки не ослаблялись.

## Linux CI и сохранённые результаты

CI готовит данные в своей PostgreSQL-базе, завершает seed-процесс, ждёт его
выхода и запускает другой PID. Только после health-проверки выполняется probe.
Реальная серия и переносимая проверка сохранённых свидетельств входят в CI.
Слияние допускается только при обеих зелёных CI окончательного коммита;
актуальный статус указан в PR №42.

[Сохранённый пакет](../evidence/sprint29/api-contract/manifest.json) содержит
только синтетические данные стенда. Проверка:
`python -I -B tools/sprint29/verify-api-evidence.py evidence/sprint29/api-contract`.
Она проверяет пять файлов, digest и ресурсы backup, все 28 названий случаев,
33 точных сочетания method/path/status, хеш отчёта и связь с внешним restart.
Проверка пакета не выполняет новые запросы и не подтверждает авторскую подпись.

Полный P3 остаётся открытым: Linux/TLS-развёртывание, производственная политика
поддержки API, общая атомарная квота проекта, OIDC по требованиям внедрения,
несколько экземпляров и HA требуют отдельной приёмки. Этот инкремент
не является нагрузочным тестом и не проверяет kill посреди вычисления.
