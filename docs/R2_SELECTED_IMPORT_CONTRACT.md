# R2: контракт выбранного импорта

Статус: **проект уточнения для отдельного обсуждения и голосования**. Этот документ не закрывает R2 и не обещает полную совместимость с Apromore. Исходный R2-02 в [ТЗ](SPRINT_08_SCOPE.md) допускает явно принятый поддержанный subset; критерии R2-01–04 сохраняются.

Уточнение составлено 21 октября 2026 после наблюдений Sprint18. Это не притворное определение, замороженное до эксперимента: исходные корпуса и ручные гипотезы были закреплены заранее и не изменяются под результаты.

## Вход и результат Rust

Выбран отдельный подтверждаемый XES preview с policy `apromore-validateLog-bbf24df-preview-v1`. Обычный строгий импорт сохраняет свои правила. Поддержан несжатый плоский UTF-8 XES: атрибуты журнала, трасс и событий, известные declarations и classifiers могут присутствовать, однако результат анализа — существующая модель `EventLog`. Идентичность активности определяется `concept:name`, а не составным classifier. Произвольные classifiers и дополнительные типизированные атрибуты не становятся полями аналитической модели и её производных экспортов.

Исходный файл сохраняется без изменения вместе с SHA256; это сохранность источника, а не аналитическое использование всех его полей. До подтверждения показываются исходные counts, identities, дополнения, удаления и отчёт об отброшенных полях/classifiers/extensions без их значений. Отчёт о потерях временный; его долговечное хранение не заявляется. Подтверждение создаёт новый результат и долговечную policy/action provenance. Историческая приёмка R2-03/04 переносится только по доказанной преемственности и затронутым регрессиям.

Порядок событий — исходный XML, без сортировки по времени; равные timestamps не меняют порядок. Case ID и ordinal отражают исходные позиции, включая пропуски после фильтрации. Отсутствующий lifecycle дополняется `complete`; допускаются `start` и `complete` без учёта ASCII-регистра, без обрезания пробелов. События без имени/времени и с неподдержанным lifecycle удаляются с указанием причин, пустые трассы удаляются. Полностью отфильтрованный preview может быть показан, но его подтверждение запрещено.

Timestamp нормализуется к UTC. Точность Rust и Java сравнивается отдельно: точное значение с долей секунды и явно обозначенное сравнение при миллисекундной точности. Потеря Java наносекунд не объявляется точным равенством. Отсутствующее имя и defaults проверяются фиксированным корпусом; наблюдённое изменение завершающего пробела при повторном чтении Java сохраняется как различие.

Global defaults, list/container и вложенные атрибуты не поддержаны и отклоняются. DTD, повреждённый XML, некорректные типы/даты и дубли семантических ключей отклоняются по строгим правилам admission. Все исходные данные проверяются до фильтрации: лимит файла 20 MiB, событий 100000, трасс 20000, activity 4096 байт. Отказ Rust на принятом Apromore входе — явное различие, а не parity PASS. Произвольные форматы Apromore и не-ASCII эквивалентность lifecycle не обещаются.

## Эталон и наблюдения

Canonical ApromoreCore закреплён на `bbf24dfd43e72d6992392465f875a4367cbe792b`. Предыдущие private importFromStream проверки выбора parser/fallback/factory/default/validateLog дополняются настоящим публичным `importLog`, а не заменяются самописной имитацией. Исполняется оригинальный неизменённый класс через Spring transaction proxy с настоящими достижимыми JPA, пользовательскими/групповыми репозиториями, H2, FILE, Ehcache и APMLog. H2 — выбранный тестовый backend; Portal HTTP login, production MySQL и `perspective=true` этим не проверены.

Новый замороженный корпус содержит 12 сценариев: личная/своя/чужая папка, private/public права, неизвестный пользователь, пустой журнал, внешний rollback, повторное имя, нормализация имени, порядок/offset/lifecycle, полная фильтрация и богатый плоский журнал. Отдельно проверяются полные типизированные значения, classifiers с порядком ключей, extensions, signed64 за пределами JavaScript safe integer, отрицательный ноль и UUID. Counts не заменяют сравнение полей.

Наблюдённые различия сохраняются: global-containing XES отклоняется Rust; Java при повторном чтении теряет завершающий пробел default name; UUID меняет регистр; Java timestamp теряет дробь меньше миллисекунды. После rollback БД могут оставаться файл и cache; при конфликте имени обнаружены внешние остатки. Полностью отфильтрованный журнал Java записывается, но после очистки cache его чтение возвращает `null`. Rust не обязан воспроизводить эти внешние остатки или принимать непригодный результат.

Пустой исходный журнал Java отклоняет, Rust может вернуть пустой preview с `fully_filtered=true`, но подтверждение запрещено: это различие admission, а не успешный импорт в обоих продуктах. Имя XLog и имя записи Log в БД сравниваются отдельно. Различие регистра UUID сохраняется как текстовое различие: равенство значений UUID не объявляется равенством исходных строк.

Десять исходных наблюдений и два целевых запуска исправленного null-наблюдателя имеют разные версии собственного адаптера, связанные проверенным carry. Это не один притворный прогон единственного бинарника. Неудачные гипотезы и собственные ошибки наблюдателя сохраняются.

## Условия приёмки

Для PASS нужны одновременно полный source/runtime provenance R2-01, принятый точный контракт и полная матрица R2-02, доказанный перенос R2-03/04, независимые QA и TechnicalDebt, CI точного кандидата и публичная воспроизводимая поставка исходников/наблюдений. Отдельное решение должно прямо назвать это уточнением поддержанного профиля. До решения статус R2 остаётся открытым; ни число примеров, ни принятие плана не заменяют приёмку.
