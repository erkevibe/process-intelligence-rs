# BPMN: подписи переходов

Статус: **проект конечного расширения R4-01, реализация ещё не разрешена**. Принятие этого списка не означает закрытие discovery, качества или всего R4.

Добавляется только `sequenceFlow.name`: импорт, отображение, редактирование, сохранение, экспорт XML и повторный импорт. Подпись — текст, а не условие исполнения. Поддержанные узлы остаются прежними: start, end, task, exclusive gateway, parallel gateway; граф, references, позиции, размеры и waypoints сохраняются по существующему контракту.

В модели flow получает `label: String`, по умолчанию пустую и пропускаемую при сериализации. Старые JSON без поля читаются; модель с пустыми подписями сохраняет прежние канонические байты. Непустые подписи старый бинарник с `deny_unknown_fields` читать не обязан: для новых данных требуется новый бинарник. Обратная совместимость чтения новых данных старой версией не обещается; перед использованием новой возможности нужна резервная копия.

Одна подпись ограничена 4096 байт UTF-8 и допустимыми XML-символами; сохраняются Unicode, пробелы и декодированные XML-sensitive символы. Серверный лимит обязателен независимо от maxlength браузера. Общие лимиты модели/экспорта продолжают действовать. Новое heap-поле учитывается в memory charge кеша. Пустая подпись не создаёт name в XML; непустая экранируется.

В браузере выбранный переход показывает подпись в общих полях выбранного элемента; editor может применить изменение и сохранить, viewer — только посмотреть. Координаты перехода в этом редакторе недоступны. Импортированный BPMNLabel DI и его bounds не поддерживаются: расположение текста определяет renderer. Условие, default flow, conditionExpression, expressions/CDATA/xsi:type, расширения и исполняемый engine остаются явными отказами. Название перехода не интерпретируется как условие.

Проверка: полное сравнение model import→edit→save→export→reimport; Unicode/XML escaping/пробелы/пустые и предельные подписи; старые JSON и байты пустой модели; malformed namespaces/duplicate IDs/broken references/условия/unsupported DI и лимиты. Реальный браузер выбирает, меняет и сохраняет переход, повторно импортирует экспорт и показывает ту же подпись после перезапуска PostgreSQL-установки. Editor write, viewer/чужой отказ и stale revision conflict проверяются на затронутом маршруте. Приёмку выполняют независимые QA и TechnicalDebt на точном кандидате.

Исторический тест отказа на named flow меняется только после явного согласования этого расширения: положительное покрытие подписи выделяется отдельно, проверки отказа conditions/default flow не удаляются.
