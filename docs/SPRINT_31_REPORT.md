# Sprint31: выполнение профиля Linux как служб

Статус: новый инкремент P3 после принятого [PR43](https://github.com/erkevibe/process-intelligence-rs/pull/43), main `711d4cbf4e895c6eb49d818bd756f185ba70d146`. Стенд реализован и прошёл независимую статическую проверку; успешный запуск systemd пока не заявлен.

Стенд запускается только на новой GitHub-hosted VM Ubuntu24.04 с PID1 systemd. Он скачивает уже проверенный release-артефакт, устанавливает его точные unit приложения, Caddyfile и drop-in, а также закреплённые официальный бинарник Caddy2.11.7 и vendor unit. Существующие пользователи, пути, units и listener-порты дают отказ. Это не установщик для рабочего сервера.

PostgreSQL18 в контейнере слушает только127.0.0.1:55449. Приложение получает отдельную роль без superuser/createdb/createrole и собственную базу. Секрет хранится root0600 и передаётся через systemd LoadCredential; URL не должен присутствовать в окружении процесса. TLS использует временный CA, без изменения глобального доверия. Отдельная цепочка firewall закрывает внешние соединения к тестовым портам Caddy; loopback остаётся доступным.

Критерии: совпадение скачанного manifest с установленными файлами и исполняемым файлом MainPID; реальные uid/NoNewPrivs; отсутствие автоматических рестартов; сохранённый отчёт и его численная проверка; включённая нулевая квота; доступ наблюдателя и отказ его записи; новый PID после перезапуска приложения; неизменность backup/report/учёта; новый SSE-запрос после перезапуска Caddy; обе службы inactive/MainPID0/успешный exit после обычной остановки.

Обычный unit приложения содержит Wants=postgresql.service: на одноразовой VM он может дополнительно запустить предустановленный PostgreSQL на5432. Эта служба не используется тестовыми данными и не останавливается скриптом. Целевой сервер данных стенда — только Docker PostgreSQL18 на55449; запуск ОС-сервера PostgreSQL этим не квалифицируется.

Файлы и пользователи остаются до уничтожения одноразовой VM. При неудачной остановке firewall сохраняется, результат не объявляется PASS. Выводы команд, ключи, cookies и исходные ответы остаются приватными; публикуется только выбранный протокол. Проверка не обещает production-допуск, публичные DNS/CA/ACME, перезагрузку всей VM, HA/SLA или непрерывный SSE-поток через рестарт.
