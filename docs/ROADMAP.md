# Роадмап Process Intelligence Core

Проект развивается от локального анализа XES к замене выбранных сценариев Apromore Core. Переход между этапами определяется результатами проверки. Оценки после первых 8 часов предварительные и уточняются по фактической скорости работы.

Спринт 03 прошёл независимую приёмку выбранного артефакта по приоритету заказчика: фиксированные сравнения с Apromore → аварийное восстановление и миграции PostgreSQL → расширение BPMN. Лимит восемь часов; публичное скачивание и окончательная проверка установки ещё обязательны до завершения поставки. [Точный план и критерии](SPRINT_03_PLAN.md), [текущий отчёт](SPRINT_03_REPORT.md). Шесть примеров с настоящим узким Java reference, первое обновление копии0.2, реальные сбои/backup и редактор задач/переходов проверены на точном новом EXE. Это не полная совместимость с Apromore.

## Этапы и результаты

Спринт 02 принят: все 12 выбранных сквозных критериев R2–R5 прошли независимую проверку, включая чистую Windows-установку и настоящий перезапуск. [Отчёт](SPRINT_02_REPORT.md), [план и A01–A12](SPRINT_02_PLAN.md), [ТЗ итерации](SPRINT_02_SPECIFICATION.md). R1 принят; исходные exit criteria R2–R5 ниже остаются в силе. CSV/сохранение относятся к R2, проекты/права/jobs к R3, ограниченный BPMN и baseline discovery к R4, фильтры и календарь с фиксированным offset к R5. Полные R2–R5 остаются частично реализованными.

### На каком этапе сейчас

| Этап | Работает в принятом ограниченном артефакте 03 | Что нужно для полного этапа |
|---|---|---|
| R1 | Принятый XES/статистика/варианты/DFG/SSE | Поддерживать регрессии |
| R2 — частично | CSV mapping, явный порядок событий, SHA256; шесть фиксированных примеров и настоящий узкий Java reference | Полный нужный legacy/XES-import oracle, timestamp/lifecycle семантика и расширенный corpus |
| R3 — частично | Вход, проекты, owner/editor/viewer, jobs; schema v1/checksum, rollback/kill, DB backup/restore, SQL deadlines и распознанный bootstrap resume | Стоимость открытия накопленных данных, дальнейшие версии миграций, audit, папки/жизненный цикл проектов и развёртывание |
| R4 — частично | Строгий BPMN subset, задачи/переходы/labels/positions, save/export, observed-variants baseline | Более полный согласованный model contract и измеренные fitness/precision; исполняемый BPMN не обещан |
| R5 — частично | Фильтры исходных трасс/действий и рабочие интервалы с fixed offset | Приоритетные остальные Core contracts, IANA/DST, conversions и Split Miner |
| R6 — впереди | Контракты хранения/задач создают основу | Измерить реальные нагрузки/RSS, затем большие данные и распределение |

После приёмки 03 следующий эксплуатационный приоритет — разнести журналы и модели по отдельным записям, убрать полное копирование проекта при изменениях и проверку всех документов внутри короткой стартовой транзакции. Финальная проверка 03 действительно достигла предела контейнера JSONB; защитный отказ с резервом для задач исправляет поведение при заполнении, но не заменяет это изменение архитектуры. Затем измерить время/RSS на накопленных данных и развить versioned migrations без увеличения тайм-аутов ради тестов. Параллельный предметный приоритет — расширить oracle до нужной семантики XES/времени и измерить качество discovery. Затем расширять проекты и BPMN по конкретным пользовательским сценариям. Объём и срок следующего спринта защищаются отдельно; это приоритеты, не обещание полного enterprise за одну итерацию.

| Этап | Плановый объём | Результат | Условие завершения |
|---|---|---|---|
| R0 Подготовка и защита | До разработки | Анализ, ТЗ, план, публичный репозиторий | Пользователь получил конкретный объём и критерии |
| R1 Первое приближение | 8 часов после защиты | XES → статистика → варианты → DFG → порог → SSE | Базовые критерии ТЗ пройдены; опубликована демонстрация |
| R2 Воспроизводимость и oracle | Оценка 2–5 рабочих дней | M0a recovery, M0b frozen outputs; CSV; сохранение данных | Legacy SHA, окружение, входы и результаты зафиксированы; расхождения описаны |
| R3 Минимальная платформа | Оценка 1–2 недели после R2 | Проекты, папки, PostgreSQL, долговечные jobs, пользователи и права | Сценарии перезапуска, изоляции пользователей и доступа проходят проверки |
| R4 Модели процессов | Оценка 2–4 недели после R3 | BPMN import/view/edit/save, выбранный miner | BPMN round trip; отдельно определённые метрики качества discovery |
| R5 Выбранное покрытие Core | Несколько итераций по 1–2 недели | Фильтры Apromore, calendars, conversions, Split Miner по приоритету | Для каждого модуля собственный контракт, corpus и проверенные допуски |
| R6 Большие данные и расширения | После измерения потребности | Arrow/Parquet, S3, OCEL, conformance, распределение jobs | Измеренные пределы памяти и производительности; отсутствие регрессий |

R2 может идти одновременно с улучшением R1, но подтверждение совместимости зависит от oracle. Восьмичасовой прототип не ожидает полного восстановления legacy; это осознанное отклонение от последовательности в обсуждении ради короткого срока.

Пользователь уточнил: R1 — первая итерация, следующие спринты продолжаются до нормального enterprise-решения. Для защиты следующего объёма Customer выделил восемь конкретных сценариев в [R2_SCENARIOS.md](R2_SCENARIOS.md); оценки сроков не являются обещанием завершить всю платформу в первом спринте.

## Порядок достижимых задач после прототипа

| Задача | Зависимости | Проверяемый результат |
|---|---|---|
| Зафиксировать ApromoreCore commit | Нет | SHA, лицензии, manifest исходников |
| Попробовать bootstrap Docker 8.1 | Рабочий Docker | Portal и один импорт, либо воспроизводимый отчёт о сбое |
| Собрать canonical Core | Java 11 и зафиксированные зависимости | Запуск Core на выбранном профиле |
| Заморозить corpus | Рабочий oracle | Входы с SHA256, параметры, golden outputs |
| CSV mapping | Event contract R1 | Колонки case/activity/time и ошибки по строкам |
| Персистентность | Контракты Log и Job | Журнал и результаты доступны после перезапуска |
| Проекты и папки | Персистентность | Создание, перемещение, удаление с проверкой принадлежности |
| Авторизация и RBAC | Пользователи и владение | Запрещённые чтение и изменение действительно отклоняются |
| BPMN viewer и editor | Модель хранения | Загрузка, редактирование, повторная загрузка того же графа |
| Discovery модели | Oracle и модельный контракт | Отдельные оценки fitness/precision, без ложного равенства XML |
| Business Calendar | Corpus времени | DST, выходные и рабочие интервалы проверены отдельно |
| Split Miner | Corpus и критерии качества | Проверенный перенос после анализа алгоритма |

## Предлагаемая карта переноса

| Область legacy | Действие | Новый компонент |
|---|---|---|
| Portal и формы | COLLAPSE | Rust handlers + HTML + Datastar |
| ZK и Spring glue | DELETE | Нет прямого аналога |
| OpenXES и импорт | WRAP + VALIDATE | Rust4PM adapter + normalization |
| DFG и варианты | REIMPLEMENT или WRAP + VALIDATE | Rust mining module |
| Process Discoverer UI | REIMPLEMENT | Datastar shell + Cytoscape |
| Model Editor | REIMPLEMENT | BPMN contract + server storage; текущий ограниченный viewer/editor на Cytoscape |
| Repository и Database | REIMPLEMENT | PostgreSQL + storage interfaces |
| Permissions и Calendar | PORT SEMANTICS | Rust с отдельными поведенческими тестами |
| Split Miner | PORT при подтверждённой потребности | Отдельный алгоритм с обязательной проверкой |
| Commercial extensions | Отдельное решение | Не входят автоматически в Core replacement |

Это план классификации, не результат полного аудита файлов Apromore. Доля DELETE и число переносимых классов будут известны после анализа конкретных модулей.

## Метрики принятия

- Feature BCR: доля прошедших сценариев из фиксированного списка прикладного поведения; непроверенные сценарии показаны отдельно.
- DFG: точное равенство частот на одинаковой нормализации и параметрах.
- Discovery: отдельные fitness, precision, simplicity и согласованные допуски; итоговая средняя оценка не скрывает провал критичной метрики.
- Performance: время и максимальная память на одинаковых данных и оборудовании; до замеров ускорение не заявляется.
- FLW: число попыток, воспроизводимость verifier, регрессии и область применимости проверенных решений.
