# BPMN fitness, precision и simplicity: проверенные диагностические результаты

Sprint19 добавляет отдельный оценщик. Он не меняет сервер 0.7.5 и пока не
предоставляет новую кнопку в интерфейсе. Исходные R4-01–03 сохраняются;
этот вклад сам по себе не закрывает весь R4.

Точная [методика](R4_QUALITY_CONTRACT_DRAFT.md), её хеш
`8e17394b9e1e79ffd0bcda4b2a55d0454feff5b3c017b91ab8e115d11f9f974d`
и конкретные ручные ожидания согласованы до реализации и измерений.
Обозначение DRAFT в неизменном файле сохраняет исходные утверждённые байты.

## Что фактически проверено

- Все 13 допущенных BPMN независимо преобразованы неизменённым PM4Py 2.7.17.
  Для них совпали полные принимающие наблюдаемые языки, включая циклы;
  сравнение не ограничивалось выборкой трасс. Пять неподдержанных или
  недопущенных BPMN не скрыты и не получили числовых оценок.
- Для 25 сетей Rust и 13 сетей независимого преобразования проверены все
  достижимые состояния и взвешенные переходы по исходным байтам сети.
- Результаты охватывают 34 конкретных случая, 54 строки «случай × модель»
  и 84 группы Rust с отдельными training/held-out входами. В 82 группах
  согласованы предусмотренные значения или статусы обеих реализаций:
  81 численная fitness, 66 численных precision и 82 structural simplicity.
  Один пустой лог даёт `no_data`; четыре группы без активируемых меток
  не получают precision=1; 11 групп с неподходящими трассами получают
  `requires_fitting_log` вместо усреднения по оставшимся префиксам.
- Две из 84 групп имеют только ограниченный результат эталона из-за
  намеренно пониженных лимитов поиска. Ещё две группы PM4Py с пониженным
  пределом состояний соответствуют отказу Rust до групповой оценки.
  Эти четыре результата эталона не засчитаны как числовые совпадения.
- Независимый проверяющий скрипт заново нашёл оптимальные стоимости,
  выполнил каждый сохранённый путь, пересчитал точные дроби, частоты,
  все минимальные tau-stop markings и множества префиксов. Шесть
  повреждений данных были независимо отвергнуты: стоимость, путь,
  частота, пропущенный случай, ребро графа и показанная метка эталона.

Обе реализации считают метрики одной и той же сохранённой сети с проверенным
SHA256. Независимое преобразование BPMN служит отдельной проверкой поведения;
его структурную simplicity не подменяют оценкой сети другого представления.
Simplicity зависит от представления и не доказывает минимальность модели.
Precision использует согласованный Align-ET профиль без конечного маркера;
его известное ограничение на необязательном завершении остаётся явным.

## Неподтвердившиеся ожидания

Три исходных ожидания точной причины отказа не подтвердились. Корпус не
переписывался после измерения:

| Случай | Ожидали | Получили |
|---|---|---|
| BPMN growth | `token_bound_exceeded` | `reachable_marking_budget` |
| conditionExpression | `unsupported_conditionExpression` | `bpmn_unsupported` |
| default flow | `unsupported_default_flow` | `bpmn_unsupported` |

В growth несколько распределений токенов достигают 10 000 состояний раньше,
чем отдельная координата достигает 256. Компактная ручная сеть того же
стрессового семейства действительно достигает токенного предела первой.
Условия и default flow безопасно отказывает неизменённый строгий парсер,
но с более общим кодом. Все эти результаты сохранены как failed hypotheses,
а не переименованы в полное совпадение. Отдельный реальный запуск проверки
эквивалентности с пределом одной пары вернул предусмотренный `inconclusive`.

## Проверка сохранённых данных без PM4Py

[Полный набор](../evidence/sprint19/bpmn-quality/manifest.json) содержит 152
проверяемых участника плюс сам манифест. Из них 150 — побайтные копии
синтетических входов, сетей, графов и измерений; два — явно производные
метаданные. В 11 записях native-процессов абсолютный путь программы заменён
именем файла; остальные поля сохранены точно, указан хеш исходной записи.
Полные исходные потоки проверены QA и остаются в частных свидетельствах;
публичный набор не выдаёт сводную запись за опубликованный полный build log.

Достаточно стандартного Python, без установки библиотек и запуска движков:

```text
python -B tools/sprint19/verify-quality-manifest.py evidence/sprint19/bpmn-quality
python -B tools/oracle/audit-quality-evidence.py --rust evidence/sprint19/bpmn-quality/rust-metrics.json --reference evidence/sprint19/bpmn-quality/reference-metrics.json --prepared evidence/sprint19/bpmn-quality/prepared --corpus fixtures/quality/corpus.json --output NEW-audit.json
```

`NEW-audit.json` должен отсутствовать. Проверяющий скрипт требует включённых
assertions и отказывается работать с `python -O`. CI повторяет проверку
манифеста и независимый аудит. Отдельные графовые, сетевые и XML-проверки
проверяют циклы, неоднозначные ветви, повреждения и точность байтовых проекций.
