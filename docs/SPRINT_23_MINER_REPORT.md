# SplitMiner: фиксированное наблюдение на 1 500 событий

Локальный результат принят независимыми QA и TechnicalDebt. Здесь сохранён
снимок кандидата перед итоговой проверкой скачанной поставки и CI; эти условия
фиксируются отдельно при приёмке PR. Версия приложения остаётся 0.8.2.

После компактных отчётов и успешного преобразования 90 000 событий выполнен
отдельный пункт R5-04: один настоящий вызов прежнего SplitMiner в свежей JVM.
Это не запуск SplitMiner на 90 000 событий и не полное закрытие R5.

## Вход и результат

Вход содержит 500 трасс `case0000`–`case0499`, каждая A → B → C:
1 500 событий, без времени и дополнительных атрибутов. Его 109 566 байт
закреплены до запуска, SHA256:
`C2196DD7376C94F17E2B6B5A4CDBE5EC620B10CA008130418ABC6D7558AF59F1`.

Исполнены прежние скомпилированные harness, observer, JDK и upstream-классы.
До и после запуска проверены два исходных набора по 5 763 файла, зависимости,
упорядоченный classpath и 504 файла JDK. Новых сборок Java или Rust не было.
Настройки сохранены: heap до 512 MiB, два видимых JVM процессора и прежние
параметры SplitMiner.

Независимый аудит проверил все поля и порядок событий до и после mining,
полную поддержанную семантику BPMN против линейного эталона и отдельное ручное
ожидание: start → A → B → C → end, пять узлов и четыре связи. Полученная BPMN
имеет SHA256 `4D0C7502010481E845BA15F2AD588E1DA4D7E60B3967AC92F015A34C79A62B7C`.
Новые fitness/precision/simplicity и перенос прежних оценок не заявляются.

| Интервал | Наносекунды |
|---|---:|
| Парсинг XES | 520 436 700 |
| Только `mineBPMNModel` | 125 033 900 |
| Экспорт BPMN | 683 716 400 |
| Активный конвейер после GO, включая наблюдение и запись отчёта | 2 363 996 900 |

Время жизни JVM дополнительно включает запуск и ожидания GO/EXIT. В пакете
сохранены отдельные отметки контроллера и CPU процесса; это не CPU только
алгоритма. Свежая JVM не означает холодный файловый кеш ОС. Загрузка ОС,
частота CPU и действия пользователя не контролировались. Одно наблюдение
не даёт медиану, SLO, пропускную способность или вывод об ускорении.

## Память и журналы

В последней живой точке ОС сообщила lifetime peak working set **171 708 416
байт** (163,754 MiB), текущий working set — 170 479 616 байт. Peak private
commit — **671 563 776 байт** (640,453 MiB), текущий private commit —
668 917 760 байт. Working set может включать общие страницы; commit не равен
физической RAM. Heap 512 MiB — настройка, а не измеренная память процесса.
Последний живой снимок не включает последующее завершение JVM. Отдельные
счётчики Job и CPU после выхода сохранены без переименования этих величин.

Четыре записи процессов — launcher, collector, Java и проверяющий сохранённые
данные — завершены с кодом 0 и полным EOF всех восьми потоков. Исходные
потоки сохранены целиком, включая строки движка:

```text
WARNING - first gateway not found
ERROR - something went wrong initializing the gateway map
```

Возвращённый полный граф прошёл проверку. Эти строки не скрываются;
отсутствие внутренних fallback-ветвей по одной идентичности класса не доказано.

## Почему 500 трасс

Первый план на 1 000 трасс / 3 000 событий остановлен **до выполнения Java**.
Инструмент сохраняет полные типизированные XLog до и после обработки; даже
нижняя граница их содержимого — 1 124 000 байт — превышает прежний предел
наблюдения 1 MiB. Это отказ допуска инструмента, а не неудачный замер алгоритма.

Отдельная заранее принятая поправка закрепила 500 трасс. Лимиты и движок
сохранены; фактическое наблюдение заняло 594 105 байт. После GO повторов,
уменьшения входа или повышения лимита не было. Прежние неудачи, UNKNOWN и
невосстановленная первая причина старого аварийного захвата не изменены.

## Самостоятельная проверка

[ZIP со свидетельствами](../evidence/sprint23-miner/observations.zip) содержит
25 файлов, 1 047 921 байт после распаковки. Размер ZIP — 37 822 байта, SHA256:
`C571D7B3C48D6DF58DAE8147F2AFD94F1897AF3B5CED14086AC29727DB5C6148`.

Из корня репозитория, с Python 3.13 и новым пустым каталогом:

```sh
mkdir -p .local/sprint23-miner-check
python3 -I -B tools/sprint23-miner/check-evidence.py evidence/sprint23-miner/observations.zip .local/sprint23-miner-check
```

В PowerShell каталог можно создать через `New-Item -ItemType Directory`,
а вместо `python3` использовать `python`. Проверяющий не запускает Java,
сервер, базу данных или другие процессы. Он сверяет фиксированный архив
до распаковки, затем повторяет полный аудит источника, BPMN, счётчиков и
исходных потоков. Результат записывается в `public-audit.json`; существующий
непустой каталог не перезаписывается. Это проверка сохранённого опыта,
а не новое измерение производительности.

Исходные потоки `.raw.stdout`/`.raw.stderr` сохраняют прежние SHA и длины.
Локальные пути заменены явными псевдонимами только в метаданных; проекция
протокола имеет отдельную идентичность. Все научные числа, их исходные записи
и значения полей сверены с оригиналами. Приватный файл владения Java явно
исключён: публичный повтор не проверяет создание Job заново. Включена точная
квитанция фактической приватной проверки; создание процесса, владение и
исходные инвентари приняты отдельными независимыми проверками.

Хеши связывают фиксированные байты и не являются подписью издателя.
Пакет не содержит JDK, JAR, исполняемых файлов, секретов или базы данных.
Прежняя серия описана отдельно в
[результатах Sprint20](R5_MINER_PERFORMANCE.md).
