# Implementation notes for the frozen conversion profile

These notes record API details and existing parser boundaries found during Sprint20. The frozen method and its57 manual cases remain unchanged; unsuccessful attempts remain in the evidence.

The method names the source modules that define the real Rust4PM PNML functions. Those modules are crate-private, but `pnml/mod.rs` publicly re-exports the same functions. The adapter must import `process_mining::core::process_models::case_centric::petri_net::pnml::{export_petri_net_to_pnml, import_pnml_reader}`. The locked module SHA256 is `B2CFF7BC7CD55736A887AA06B77846F709E30FA91FE2C3A3D79D80B8B6B757A5`. This corrects the adapter's Rust import route; neither function body, dependency nor conversion semantics is replaced.

The unchanged production XES parser requires an event activity to contain a non-whitespace character. A CSV activity made only of whitespace therefore cannot be represented through that actual parser and must receive an explicit `production_xes_parser_refused` report, including when metadata loss is allowed. The converter must not trim, rename or invent an activity. An external-file refusal probe is specified before its execution; it adds no successful-format claim and does not change the frozen fixture expectations. Trace names retain the separately declared identity rules.

Successful publication stages complete synchronized payload/report files and uses exclusive names. Ordinary publication errors roll back only names created by that invocation. This is not a guarantee that two separate directory entries appear atomically or that a power failure cannot leave an intermediate directory state.

Independent review found that the first working C2 reports named normalization categories without their actual locations and counts. The supplemental `evidence.normalization_inventory` records only occurrences in the actual source and target: PNML net/page/arc IDs, place display names, tau local-node markers, and the complete source-to-target node ID mapping. XML locators use zero-based siblings per element name; JSON locators use RFC6901 pointers. Values are decoded field values, while exact original lexical bytes remain bound by payload hashes. Counts are derived from the entries; absent fields produce no entries. This repairs the report contract without changing codecs, manual fixtures, graph semantics or loss permissions. Earlier successful semantic checks do not constitute acceptance of the earlier incomplete inventory.
