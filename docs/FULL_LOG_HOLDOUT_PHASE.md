# Контроль полного профиля вне обучения

Протокол зафиксирован до запуска. Те же закреплённые Procure-to-Pay CSV
и исходный порядок событий. Для каждого исходного case_id берётся SHA256
его точной UTF-8 строки. Первые восемь шестнадцатеричных цифр трактуются как
целое; остаток0 при делении на5 означает контроль, остальные — обучение.
Разбиение не меняется по результатам качества. Случаи не пересекаются и
вместе дают весь full-журнал. Учебные fast/slow для этой проверки не используются.

Построитель получает только обучающие варианты. Контроль читается после
построения модели. Фиксируются хеши обоих входов, модель, все случаи/события,
fitness и precision по прежней методике каждого профиля. Невоспроизводимый
контрольный случай не отбрасывается: precision получает requires_fitting_log.
При недостающей метке или поисковом пределе сохраняется явный исход.

Это один заранее выбранный holdout внутри учебного источника, не проверка
на другом предприятии и не доказательство статистической надёжности.
Новый алгоритм или параметры по этой выборке не подбираются.
