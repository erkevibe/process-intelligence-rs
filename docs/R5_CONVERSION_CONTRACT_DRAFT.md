# R5-03 prospective conversion contract

Status: METHOD AND MANUAL INPUT PROPOSAL BEFORE IMPLEMENTATION. The frozen method and independent manual fixtures require QA, TD, PM, Customer and Root agreement before converter code or native execution. These two named pairs establish bounded conversion support; they do not promise every XES, CSV, PNML or Petri dialect. The existing 075 runtime remains unchanged.

## Generic CLI and atomic results

The proposed additive example is pi_convert FROM TO INPUT NEW_OUTPUT_DIRECTORY [--allow-metadata-loss]. FROM/TO are xes/csv and petri-json/pnml in the four supported directed pairs only. It accepts arbitrary admitted external input, not IDs from a fixture manifest. Input is a regular non-reparse UTF-8 file, at most 20 MiB. Output directory must not exist. Complete validation and in-memory conversion precede payload publication. A successful new directory contains payload.csv, payload.xes, payload.pnml or payload.json plus report.json. Refusal may create a new directory containing only report.json; it must never publish a partial payload or overwrite any file. Output payload is bounded to 20 MiB; report to 4 MiB. No network, subprocess, DTD/entity resolution, source-sidecar inverse, saved-source payload or environment contents are allowed.

Report v1 binds actual input SHA256/bytes, direction/profile/version, locked dependency/source pins, policy flag, output SHA256/bytes or null on refusal, status/reason, complete typed metadata omissions and normalizations with source locations/counts, source/target semantic summaries and actual ID bijection where relevant. Source offsets, trace/event indexes or JSON pointers identify affected fields. Actual parser warnings are retained separately from conversion losses, unmodified; a standing parser compatibility warning is not an observed loss. No report claims a successful roundtrip until a separate real inverse conversion has executed. Refusal, unsupported, loss-refused and size-limit are distinct reasons, never numerical defaults.

XML reference policy for both C1 XES and C2 PNML: the five predefined references &amp;, &lt;, &gt;, &quot;, &apos; (lexically amp, lt, gt, quot, apos) and numeric character references resolving to legal XML1.0 characters are admitted and decoded exactly. DTD declarations and all DTD-declared, non-predefined general or external entity references remain forbidden; no resolver/network/file access is permitted. The direct manual PNML A &amp; β label decodes to A & β, the XES &quot;β&quot; fragment decodes to quoted β, and numeric &#10; in line&#10;break is exactly one LF character. These admitted character references are not metadata omissions.

## C1 flat XES and RFC4180 CSV

CSV profile is UTF-8, comma delimiter, exactly case,activity,timestamp,lifecycle as the first and only core columns, with RFC4180 quoting/doubled quotes/CRLF serialization. Strict lexical preflight rejects malformed quoting, duplicate headers, variable field counts, missing/reordered core columns, invalid UTF-8, NUL and unescaped control characters. Additional uniquely named columns are metadata and require --allow-metadata-loss with every nonempty cell inventoried; no core field may be remapped implicitly. Blank physical records are refused, not silently skipped. Header-only CSV is the independently testable empty log. Core null timestamp/lifecycle is an empty cell; an actual empty-string XES lifecycle is unrepresentable and is refused even with loss allowed.

Flat XES profile is one unprefixed log with the conventional optional default namespace http://www.xes-standard.org/; direct trace children and direct event children; concept:name string, time:timestamp date and lifecycle:transition string have their exact scope/type. Root xes.version=1.0 and the namespace declaration are format declarations, not omitted log attributes; they appear as preserved/normalized format declarations in reports, with zero metadata-loss count. No other root attributes are silently accepted. Supported extra scalar metadata types are string, date, int, float and boolean with validated values and unique keys per scope. Integer metadata is signed-i64 decimal, float is finite valid f64 decimal (never NaN/Infinity), boolean is exactly true or false, date follows the timestamp lexical restrictions. Extra scalar attributes at log/trace/event scope, declared extensions/classifiers and log concept:name are metadata omissions in CSV: default refuse, explicit metadata-loss flag inventories each occurrence and permits only those omissions. Global defaults are always refused, including with loss allowed, matching the actual event_io parser; they are never dropped or expanded by a hidden preprocessing pass. Nested/list/container attributes, duplicate keys, wrong core types, malformed dates, unknown structure/namespaces, DTD declarations, DTD-declared, non-predefined general or external entity references, PI/CDATA and extension semantics outside this inventory are refused with or without the flag. Empty extension declarations do not invent metadata values. Numeric metadata is validated before being omitted.

Trace concept:name must be present, nonempty and unique. Every represented trace has at least one event. Missing/duplicate/empty names and empty traces are refused even with metadata loss: merging case identities or dropping traces/events is prohibited. Empty log with zero traces is admitted independently; it becomes the exact header-only CSV. Event activity is nonempty and at most4096 UTF-8 bytes; lifecycle, if present, is nonempty. Limits match existing parsers: <=20000 traces and <=100000 events. XML10 text legality is enforced before writing.

Trace order and each trace's event order are preserved; no timestamp sorting and no lifecycle merging. CSV case rows must be contiguous, with first-appearance case order; a case reappearing after another case is refused, including allow-loss. This avoids silently losing cross-case CSV row order during XES grouping. Internal generated Case.id and Event.ordinal are parser implementation identities: reports expose the existing parse results, but equivalence is defined on ordered trace names and ordered core events, not parser-generated global versus per-trace ordinals. Source row/XML offsets remain report provenance; they are not copied into the inverse payload.

Timestamp semantic value is exact UTC instant at nanosecond precision. RFC3339 offset is mandatory, fractional digits <=9; excess digits, naive/invalid dates and leap-second forms are refused before parsers can default or truncate. Canonical output is UTC Z with shortest exact 0..9 fractional digits. Changing lexical zero-offset/fractional-zero formatting is a declared normalization, not instant loss. A nonzero original UTC offset is metadata lost by the existing UTC domain and requires explicit metadata-loss flag; report each original lexeme/location/offset and normalized instant. Nonzero offset never changes the instant or lowers precision. Missing remains missing. CSV and XES writers must independently escape every field; actual XES writer is new and cannot be replaced by a JSON sidecar. Quoted CSV embedded LF/CR characters are actual field characters, not backslash-n escapes. XES attribute serialization uses XML character references for LF/CR/tab so attribute-value normalization cannot replace them with spaces; ampersand, angle brackets and quotes are escaped. Direct manual Unicode activity line-LF-break must survive both directions as the same character, not the six-byte text backslash-u000a.

Actual library paths: existing src/event_io.rs parse_xes and src/csv_io.rs parse_csv with explicit four-column CsvMapping and NormalizationOrder::Source. Their preflights alone are insufficient for this strict conversion profile, so additive wrappers validate and inventory original input first. CSV serialization uses the already locked csv writer; XES serialization uses already locked quick_xml Writer. The converters must call the actual existing parsers, not a hand-built mock EventLog.

Manual oracle compares direct target fields and exact CSV core bytes for named cases, canonical ordered core events for direct XES targets, loss counts/reasons, and both separately executed roundtrips. Lossy inverse is compared only with the independently frozen core projection; loss report never purports to restore omitted metadata or timezone offsets.

## C2 process_mining0.6.2 native Petri JSON and named PNML

Native JSON schema is the actual PetriNet serde object: exactly places, transitions, arcs, initial_marking and final_markings; places map UUID to {id:sameUUID}, transitions map UUID to {id:sameUUID,label:null|string}, arcs contain exactly from_to:{type:PlaceTransition|TransitionPlace,nodes:[UUID,UUID]} and weight:u32. Markings map place UUID to u64; final_markings is null or an array of markings. Duplicate JSON keys at every depth, unknown/missing fields, invalid UUIDs, key/internal-ID mismatch, same ID across place/transition, dangling references, wrong partitions, duplicate directed endpoint pairs, malformed/negative/fractional/overflow integers and weights0 are refused before serde can ignore/default. No graph simplification or behavioral execution is part of conversion. Duplicate transition labels are admitted; node identity cannot be inferred from labels.

Admitted bounds:1..128 places,0..128 transitions, <=256 nodes total, <=1024 arcs, <=32 final markings, label/id-reference text <=4096 UTF-8 bytes, nesting <=32. Token counts retain full u64 and arc weights full positive u32; no aligner u8/token255 restriction applies. Labels are null (tau) or nonempty XML10 string with no leading/trailing Unicode whitespace, CR or LF, because upstream PNML import trims text and XML normalizes line endings. Interior Unicode/spaces/XML escapable characters are admitted. Empty/trim-sensitive labels are refused, not transformed into tau. No token firing, soundness requirement or forced reachable language is introduced.

Missing marking versus zero is explicit: initial_marking=null is admitted; a present initial map must contain at least one explicit place entry, including a zero count if intended. Some({}) is refused because upstream import collapses an empty map to None. final_markings=null or nonempty array is admitted; Some([]) is refused because upstream import collapses it to None. An empty final marking {} inside a nonempty final array is admitted and distinct from a missing final set. Explicit zero entries in nonempty initial/final maps remain entries and must survive. Final-marking order is preserved; no deduplication.

PNML profile is the exact unprefixed pnml/net/page structure used by the real exporter: one net, one page, ordinary weighted arcs, place/transition/name/text, initialMarking/text and net-level finalmarkings/marking/place idref/text. The net type URI is http://www.pnml.org/version-2009/grammar/pnmlcoremodel; no schema/network fetch. Root namespace absent only. IDs are nonempty unique bounded strings, node IDs disjoint; arc IDs unique. Arc endpoints must be opposite known node kinds, and no duplicate directed endpoint pair. Every arc has exactly one positive-u32 inscription/text; no implicit weight1. Numeric texts use canonical unsigned decimal (0 or nonzero leading digit); whitespace, negatives, overflow and empty numbers are refused before upstream unwrap_or_default/unwrap_or(1). Initial/final references and entries are unique and valid. Unknown attributes/elements, extra pages/nets, reference nodes, inhibitor/reset/read arcs, colors, capacity, graphics, toolspecific extensions and malformed XML are refused. Place name is absent or exactly its own ID (the exporter-generated display text); a different place name is unrepresentable metadata and refused even with loss flag. Node names in the graph are transition labels; distinct display metadata is not claimed preserved.

Sole toolspecific exception is a transition tau marker with exactly tool=ProM,version=6.4,activity=$invisible$,localNodeID=UUID, at most once. Its name/text must be Tau, matching the actual exporter. Only this marker maps label to null; a visible literal Tau remains a visible label. Its generated localNodeID, net ID/page ID, XML whitespace, place name equalID and regenerated arc IDs are format identifiers/normalizations recorded explicitly, not execution semantics or hidden sidecars. All labels, node kinds, exact weighted arcs and each explicit initial/final entry must be conserved.

Actual upstream calls are process_mining::core::process_models::case_centric::petri_net::pnml::import_pnml::import_pnml_reader and export_pnml::export_petri_net_to_pnml, with native PetriNet serde JSON. Neither function is replaced or patched. XML preflight builds the expected semantic graph keyed by original node IDs. Upstream importer assigns random UUIDs, so converter must record and independently verify a complete place+transition bijection from actual parsed source IDs to actual imported IDs. Observation must not assume hash-map iteration order or match duplicate labels arbitrarily. A permitted implementation technique is compare original source stream creation order against an independently captured real import result only if an actual unique correspondence is proven; otherwise use an independent full colored weighted graph-isomorphism check, bounded search <=100000 partial assignments, and report inconclusive on cap. A whole structural isomorphism with labels, arcs and all markings is mandatory, not sorted-label/count equivalence. Exported UUID IDs are directly inspectable; compare native JSON against direct PNML target under identity mapping before inverse import. Ambiguous automorphisms may yield any verified full bijection; no fabricated original UUID preservation claim.

Both roundtrips independently verify actual target graphs against frozen manual expected graphs and full node bijection. UUID/map/order/format normalization is allowed only where explicitly declared. --allow-metadata-loss grants no additional PNML semantics, labels or markings; unsupported fields remain refused. Static unknown-construct and security cases are tested before invoking best-effort importer.
