# Диагностика объёма PostgreSQL

Скрипт [capacity-diagnostic.sql](../tools/sprint24/capacity-diagnostic.sql)
читает количество проектов, шесть известных видов записей и физические
размеры пяти управляемых таблиц и текущей базы. Он не читает содержимое
документов, аккаунтов или сессий и не запускает миграцию.

Нужен PostgreSQL 18 и база с известными таблицами V3 и записями миграций
1/2/3. Это минимальная проверка структуры для отчёта, не проверка всей
схемы или контрольных сумм миграций. Неизвестный вид записи, неподходящая
схема или недостаточные права приводят к отказу. Используйте роль с SELECT
на перечисленные таблицы и правом измерения размера базы. Доступ задайте
через существующий защищённый профиль подключения PostgreSQL; не помещайте
пароль в командную строку или публикуемый отчёт.

Пример для настроенного профиля `process_intelligence`, PowerShell 7:

```powershell
psql -X -q -A -t -v ON_ERROR_STOP=1 -d 'service=process_intelligence' -f tools/sprint24/capacity-diagnostic.sql > capacity.txt
$reportExit = $LASTEXITCODE
if ($reportExit -ne 0) { throw 'Отчёт не завершён; сохраните вывод для диагностики.' }
```

Успешный вывод содержит ровно две непустые строки: один JSON-объект и
`CAPACITY_DIAGNOSTIC_COMMITTED_V1`. Маркер появляется отдельным запросом
**после COMMIT**. Нужны одновременно этот формат, маркер и фактический код
завершения `psql` 0. Один JSON без маркера, ненулевой код или обрезанный
вывод означают незавершённый отчёт. Частичный файл сохраняйте для разбора;
не принимайте его за пустую базу. Запускайте с `-X` и `ON_ERROR_STOP=1`,
как в примере: пользовательский psqlrc и продолжение после ошибки меняют
контракт выполнения.

Транзакция работает в REPEATABLE READ READ ONLY. Ограничения: пять секунд
на SQL-команду, две на ожидание блокировки, десять на транзакцию. При
крупной базе отчёт может отказаться по тайм-ауту; это не доказательство
повреждения данных. Не увеличивайте ограничения ради принятия неполного
результата.

`project_count` и `record_counts` относятся к логическому снимку транзакции.
`observed_at` отмечает измерение, но физические файлы во время него могут
меняться. REPEATABLE READ не замораживает размер на диске.
`table_including_toast_bytes` включает TOAST, `indexes_bytes` учитывает
индексы, а `total_bytes` — их общий размер. Размеры таблиц входят в размер
базы: **таблицы и базу нельзя складывать**. Это физические наблюдения,
а не квота или оценка безопасной максимальной нагрузки. WAL, другие базы,
резервные копии и свободное место файловой системы сюда не входят.

Описание функций размера: [PostgreSQL 18](https://www.postgresql.org/docs/18/functions-admin.html#FUNCTIONS-ADMIN-DBSIZE).
Границы READ ONLY и снимка: [управление транзакцией](https://www.postgresql.org/docs/18/sql-set-transaction.html).
Фактические проверки и их ограничения фиксируются отдельно в отчёте
Sprint24; сама инструкция не является подтверждением успешного запуска.
