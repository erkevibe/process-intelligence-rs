# Sprint24: путь резервного архива

Исправлен подтверждённый дефект локального `tools/database-backup.ps1`:
лексическое ограничение `.local` пропускало путь через junction в соседний
каталог. В изолированном опыте скрипт изменил DACL обычного каталога за ссылкой
ещё до отказа из-за отсутствующего конфига. Опыт использовал только синтетические
файлы внутри частного каталога испытаний. Повышение привилегий, утечка реальных
данных или запись реального архива этим опытом не показаны.

## Изменение

До создания каталогов, изменения DACL, чтения конфига и вызова PostgreSQL
проверяется сама `.local` и каждый существующий компонент обоих путей:
архива и `<архив>.manifest.json`. Ссылки/reparse points, неверные типы родителей
и каталог вместо файла отклоняются. Отсутствующие обычные каталоги допускаются.
Существующий архив **или** манифест запрещает новое резервное копирование.
Восстановление требует существующей пары файлов и допустимого имени новой БД.
После создания обычного родителя пути повторно проверяются до изменения DACL.

Сравнение границы учитывает регистр файловой системы: без учёта регистра в
Windows, с учётом на других ОС. Это не означает поддержку полной цепочки
резервного копирования с Windows ACL на Linux. Четыре вызова PostgreSQL и
семантика транзакционного восстановления не изменены. В поддерживаемом скрипте
использованы API, доступные в Windows PowerShell5; нового запуска полной цепочки
в PowerShell5 в этом опыте нет. Исторические ограничения сохраняются.

## Фактические опыты в Windows

Исходник до исправления: `B87418A14D3E299446C9DA3E0E7DC6BE0445B5114F43D793B5B67DB41805D8A0`.
Исправленный исходник: `368906C5D863B05F140BD6B502678D92023D590AABF3EBD22DDB65E152927B57`.
Контроли: `407DC0923E6A77B15733C39949D6584F13B6B8E9B68F1CDD015000CBC340255C`.

1. Точная копия прежнего скрипта получила обычного родителя через junction.
   Разрешения внешнего для установки синтетического каталога изменились:
   два разрешающих правила стали одним. Файл-свидетель сохранил байты;
   архив не создан, настоящий конфиг не прочитан, PostgreSQL не запускался.
   Ссылка удалена нерекурсивно, приватные права восстановлены и перечитаны.
2. Исправленный скрипт прошёл 12 отрицательных контролей: ссылка в `.local`,
   ссылка в родителе для Backup и Restore, ссылки в обоих конечных именах,
   сломанная ссылка, занятые архив/манифест, файл вместо родителя, каталог вместо
   файла, отсутствующая пара Restore и соседний `.local-other` вместо `.local`.
   DACL внешнего корня/дочернего каталога, самой `.local` и фактического родителя
   сравниваются до и после; применимые состояния, содержимое и коллизии неизменны.
3. Три обычных пути допущены до преднамеренного отказа отсутствующего конфига:
   существующий родитель, новый вложенный родитель, допустимый вариант регистра
   `.LOCAL` в Windows. Приватная DACL фактически перечитана. Это проверка допуска
   пути и локальных прав, **не** успешного database backup/restore.

Итого приняты 7 вызовов программ и 14 полных приватных потоков: контрольный
опыт с прежним скриптом вместе с двумя проверками ресурсов, отдельный опыт ACL,
исправленные Windows-контроли вместе с двумя проверками ресурсов. Все завершились
с кодом0. Процессы Git и публикации учитываются отдельно. Родительская очистка
проверяет все шесть известных мест ссылок, удаляет только точные ссылки без
рекурсии и восстанавливает приватные права испытательных каталогов до обхода
ресурсов. Ограничения объёма и времени обхода не повышались.

Первый контрольный опыт завершился ошибкой `private_directory_rules`:
неизменённый сохранённый объект DirectorySecurity не записал исходную DACL назад.
Его коды0/1/0 и полные потоки сохранены; этот опыт не принят как воспроизведение
дефекта. Отдельный фактический контроль подтвердил поведение дескриптора.
Свежий явно заданный дескриптор с фактическим перечитыванием исправил оснастку;
затем новый опыт проверил обычный дочерний каталог через предка-junction.

## Свидетельства и повторение

`evidence/sprint24/backup-path/summary.json` — явно **производная** сводка,
сверенная независимыми QA и TechnicalDebt с приватными оригиналами.
Она содержит исходные хеши каждого случая и SHA256 точных UTF-8 строк SDDL/состояния
без BOM или нормализации. Исходные SDDL с идентификатором локального аккаунта
остались приватными. У выбранных безопасных файлов manifest различает исходные
байты и буквальную замену домашнего пути. Содержащий SDDL исходный stdout
контрольного опыта не публикуется; полноту приватных захватов проверяли аудиторы.
Локальные акты сохраняют состояние до CI и проверки скачанной поставки.
Отсутствующий каталог, файл вместо каталога и непрочитанный ACL сломанной ссылки
представлены отдельными строковыми состояниями; их хеши не означают измеренную DACL.

Повторить контроль путей из каталога исходников, в новой пустой тестовой папке:

```powershell
New-Item -ItemType Directory .local/sprint21/root/sprint24/manual-backup-check
pwsh -NoProfile -File tools/sprint24/backup-path-controls.ps1 -Source "$PWD/tools/database-backup.ps1" -SourceSha 368906C5D863B05F140BD6B502678D92023D590AABF3EBD22DDB65E152927B57 -Fixture "$PWD/.local/sprint21/root/sprint24/manual-backup-check"
```

В Windows ожидаются 15 PASS. В Linux тот же сценарий выполняет 13 отрицательных
контролей; два Windows-контроля обычного пути явно пропускаются. Регистр `.LOCAL`
в Linux проверяется как отказ. Отказ ОС создать ссылку — ошибка испытания,
не положительный результат; не отключайте защиту ради прохода. Сценарий сохраняет
синтетические файлы, удаляет ссылки в finally и не запускает PostgreSQL.

Проверяются уже существующие ссылки и коллизии имён. Это не атомарная защита
от конкурентной замены каталогов, не новый прогон полного backup/restore,
не HA/PITR и не полная enterprise-готовность. Атомарная квота проекта остаётся
[следующим отдельным объёмом](ENTERPRISE_QUOTA_PLAN.md).
