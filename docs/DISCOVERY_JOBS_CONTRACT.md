# Сохраняемое построение BPMN: контракт 0.10.0

Эксперимент принят в PR40. Сохраняемый продуктовый путь реализован в PR41; локальная и независимая приёмка завершены. Перед слиянием обязательны обе CI окончательного коммита.
При допуске structured_variants_v1 его название и ограничения сохраняются в UI,
модели и экспорте. Внешние Java/Python не становятся зависимостями сервера.

## Приём и исполнение

- Выбор журнала, точной analysis_version и одноразового request_key. Запрос
  сохраняет канонические weighted variants и источник до ответа202/303.
- Отдельные discovery metadata/artifact records; существующие quality exports
  остаются прежнего формата. До8 задач/64 часовых квитанций на проект.
- Общие два места операций и один CPU. Не считать отдельный JobStore отдельной
  квотой. На каждой стадии — отмена, права, точная ревизия и срок.
- Стадии: queued, discover, validate, training_evaluation, publish, terminal.
  Оценка на обучении явно названа обучающей; она не доказывает обобщение.
- Один атомарный commit публикует StoredModel, результат artifact и completed.
  Model ID выделяется под mutex только при публикации; заполненные64 места
  дают явный отказ, без полумодели или ложного completed.
- Отмена и публикация используют существующий Job mutex. Отзыв прав, смена
  ревизии или ошибка хранения не оставляют подтверждённого результата.
- После перезапуска queued/running становятся interrupted. Повтор явный,
  использует сохранённый вход, новый ID и request_key; replay распознаётся до
  чтения уже удалённого оригинала. Удаление задачи оставляет часовую квитанцию.

## Сохранность и происхождение

Новая схема v5 вводится явной offline migration v4→v5; прежний бинарник0.9
должен отказать до записи, что проверяется полным снимком. Старые checksum DDL
не переписываются. Backup/restore и индексы включают discovery records;
недоверенный результат заново проверяется под общим сроком и CPU-допуском.

StoredModel получает optional training identity: project/log, analysis_version,
source_sha256, canonical variants_sha256, algorithm и parameters/method hash.
Старые модели сохраняются без выдуманной точной идентичности обучения.
Оценка отличает точное обучение, тот же журнал с изменившимися данными и
другой журнал; другой журнал сам по себе не доказывает независимость данных.

Изменение только версии собственного Cargo package не должно менять метод
оценки. Перед bump требуется сохранить fingerprint0.9 для идентичных kernel,
BPMN bridge и dependency lock; нормализуется только собственная package-version,
остальной lock/source остаётся в fingerprint. Проверка старого настоящего
численного отчёта новым CLI и отказ согласованной подделке обязательны.

## Приёмка

Обычный browser POST → сохранённая задача → модель → оценка отдельного control
журнала → BPMN export/reimport. Проверить replay/удаление/перезапуск/отмену,
отзыв прав, stale revision, quota, backup/restore и старый бинарник. Не объявлять
инкремент готовым по одному unit test или по экспериментальной таблице.
