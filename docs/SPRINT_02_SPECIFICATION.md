# ТЗ второго восьмичасового спринта

Версия 0.2, 10 октября 2026 года. Утверждённый объём и неизменные критерии A01–A12 — [SPRINT_02_PLAN.md](SPRINT_02_PLAN.md). Эта итерация реализует выбранную цепочку R2–R5; исходные этапы целиком не закрывает. Приёмка — только после независимых проверок зафиксированной версии.

## Пользовательский результат

Первый запуск предлагает создать локальную учётную запись. Пользователь входит, выбирает проект, загружает CSV или XES, получает анализ, задаёт фильтр и рабочее время, строит либо импортирует BPMN, меняет подписи и расположение узлов, сохраняет и экспортирует результат. Перезапуск сохраняет данные. Резервная копия восстанавливается в новый проект с новым владельцем; исходный проект остаётся доступным.

## Разделение задач

1. R2: CSV preview первых пяти строк, выбор case/activity/time/lifecycle и разделителя; правила порядка и исходный SHA256. Проверка эквивалентности синтетическому XES, ошибок с номером строки и неизменности предыдущего результата.
2. R3: PostgreSQL, стабильные IDs внутри проекта, транзакции, сохранённые параметры представления каждого пользователя; проекты, роли и локальный вход. Проверка двух независимых сессий, известных чужих IDs и настоящего перезапуска.
3. R3: долговечные фоновые задачи. Принятая задача записывается до ответа 202; log и completed — одной транзакцией. Отмена принимается после записи в БД под общим с публикацией lock. Queued/running после перезапуска получают failed/interrupted и не публикуются повторно.
4. R3: резервная копия с версией и SHA256; восстановление данных и создания нового проекта одной транзакцией. Неверная версия, хеш или контракт данных отклоняются до изменений.
5. R4: строгий BPMN subset, диаграмма и редактор подписей/координат; сохранение и XML round trip. Отдельный baseline discovery `observed_variants_choice_v1` воспроизводит точные наблюдённые варианты, включая пустые трассы; не оценивает параллелизм и обобщение.
6. R5: AND-предикаты трассы на исходных событиях, затем проекция действий; пустые трассы сохраняются, статистика пересчитывается. Календарь с фиксированным UTC offset, выбранными днями недели, рабочим интервалом и праздниками.
7. Поставка: чистая сборка, регрессии R1, браузерная цепочка, сценарии отказа, независимые QA/TD/Customer и итоговый СОВЕТ FLW. Все двенадцать критериев обязательны; отсутствующие доказательства обозначаются unverified.

## Контракты

CSV: UTF-8, comma/semicolon/tab, уникальные непустые заголовки. Метки действий и имена трасс сохраняются без trim. Timestamp — RFC3339 с offset. Source сохраняет исходный порядок; timestamp требует времени каждого события, сортирует внутри трассы и сохраняет исходный порядок при одинаковом времени. Lifecycle each-event: start/complete не склеиваются. XES сохраняет валидированный контракт R1.

BPMN: один неисполняемый process; start/end, обычный task, exclusive/parallel gateway, sequenceFlow и поддерживаемый DI. IDs, связи, подписи, координаты и waypoints сохраняются. Conditions, event definitions, specialized tasks, subprocesses, collaboration, extensions и неизвестная семантика отклоняются. Лимиты: 1 MiB XML/JSON модели, 1000 узлов, 4000 переходов, 4096 UTF-8 bytes подписи, конечные координаты ±1 000 000. Превышение discovery capacity — ошибка, без обрезки модели.

Календарь: weekdays 1–7 (понедельник–воскресенье), offset от −840 до +840 минут, интервал в пределах суток `[start,end)`, праздники YYYY-MM-DD. По умолчанию UTC, понедельник–пятница, 09:00–18:00. Длительность трассы — пересечение рабочих интервалов с `[min(timestamp),max(timestamp))`; отсутствие timestamp обозначается unverified. Нет IANA zones/DST и склейки lifecycle. Максимальный проверяемый span — 3660 дней.

Хранение: PostgreSQL `pi_kv` с JSONB-документами auth и каждого проекта, revision для optimistic concurrency, общий allocator ресурсов. Обновление проекта — транзакция с проверкой revision; память заменяется после commit. Восстановление нового проекта и его владельца — транзакционный batch. Это компактное хранилище локальной итерации; нормализованная схема, migrations, streaming больших данных и измеренный предел общей памяти относятся к следующим спринтам.

Backup v1 содержит журнал, исходный нормализованный журнал, анализ, политики, модель и завершённые состояния задач. Исходные resource IDs сохраняются в новом project scope; новые ресурсы обходят уже занятые IDs. Ownership и `project_id` относятся к новому проекту. Membership, password hashes и sessions не входят в bundle. SHA256 считается по сериализованному JSON payload; сохранять и загружать нужно исходный файл без пересериализации. До 20 MiB на bundle; незавершённые задачи и превышение размера явно блокируют создание копии.

## Доступ и запуск

Только loopback. Owner управляет membership, editor изменяет содержимое, viewer читает и экспортирует. Сервер получает actor/role из своей сессии и проверяет все маршруты проекта; поля user/role клиента не служат полномочиями. Admin создаёт пользователей и не получает автоматически доступ к их проектам. Параметры представления хранятся отдельно по пользователям.

Argon2id password hashes, случайные session tokens, в БД хранится SHA256 token. Cookie HttpOnly/SameSite=Strict, TTL восемь часов, не более 256 активных сессий. До 64 пользователей и 64 проектов. Обработка credentials ограничена двадцатью попытками за минуту на экземпляр. Cross-origin и неподходящий Host отклоняются. Секреты PostgreSQL находятся в защищённом `.local` и не печатаются.

Одна Platform instance на БД, enforced PostgreSQL advisory lease. Потеря рабочего соединения блокирует защищённые запросы и готовность health до перезапуска приложения. Несколько экземпляров, shared deployment, SSO/MFA, TLS и distributed jobs не входят в эту поставку.

До восьми журналов на проект; при заполнении постоянного проекта следующий импорт отклоняется и прежние журналы сохраняются — для продолжения можно создать новый проект. 20 MiB, 100 000 событий, 20 000 трасс и 4096 UTF-8 bytes метки на импорт. Последние восемь terminal jobs и выполняемые задачи, максимум две принятые задачи и две загрузки для всей платформы; CPU обработчик mining один. До 64 моделей на проект; два CSV previews с TTL пять минут. Календарь принимает до семи weekdays и 3660 праздников. Эти лимиты не заменяют измерение общего потребления памяти.

## Остаток после итерации

R2: frozen legacy oracle/corpus и объяснённые расхождения. R3: папки, migrations, audit trail, операции удаления/перемещения, восстановление инфраструктуры и расширенная security review. R4: необходимая дополнительная BPMN-семантика, редактирование структуры, качество discovery на corpus. R5: выбранные Apromore filters/conversions, IANA/DST, lifecycle duration и Split Miner. Enterprise-готовность зависит от последующих приёмок и измерений.
