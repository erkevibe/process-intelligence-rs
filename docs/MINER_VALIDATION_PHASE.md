# P2: вторая фаза, до новых Alpha-профилей

Зафиксирована 24.10.2026 после первой exploratory серии и до запуска двух
профилей ниже. Исходные отказы относятся к старому developer-профилю
`src/discovery.rs`: balance1, fitness0, replay0, repair thresholds10000,
DFG thresholds1/0. Их нельзя переносить на все реализации Alpha+++.

Кандидаты закреплённого process_mining0.6.2:

- `alpha-default`: ровно `AlphaPPPConfig::default()` — balance0.2,
  fitness0.75, replay0, skip/loop repair2, absolute DFG10, relative DFG0.1.
- `alpha-repair`: те же параметры, кроме absolute DFG1 и relative DFG0.
  Это отключает фильтрацию DFG, но не обещает fitting/soundness результата.
  Настройки выбраны по правилу сохранения малочастотных наблюдений, без
  подбора чисел по контрольным метрикам.

Новые validation inputs — `fixtures/sprint27-miner-validation/corpus.json`:
две параллельные цепочки с невиданными переплетениями, необязательный шаг,
более длинные повторения, редкий допустимый маршрут рядом с шумом,
незнакомая контрольная активность и пустой вход. Контроль не передаётся miner.
Для незнакомой активности ожидается честное несоответствие, а не новое действие
в модели. Старый корпус остаётся exploratory, новый не используется для
подстройки параметров после запуска. Сначала та же конечная проверка сети,
эквивалентность Petri→BPMN, повтор и независимые численные проверки.

Два повторения — проверка повторяемости, не статистический benchmark.
Native peak working set/commit читаются из retained handle после реального
exit и охватывают создание/завершение процесса. Калибровка 0/32MiB показала
разницу 33513472 байта; current post-exit memory не используется как peak.
Время native creation→exit включает короткое pre-resume ожидание launcher;
внутреннее время Java — только вызов miner, Rust adapter time включает
преобразование и сохранение upstream provenance. Эти интервалы не смешиваются
в одну цифру ускорения. Ресурсные пределы прежние, профиль оценщика1000 состояний.
