# Прикладные сценарии следующей итерации

Customer предложил этот порядок независимо от авторов приложения. Это вход для защиты R2 после фактической приёмки R1, не текущий объём первого спринта. Длительность R2 пересчитывается по его результату.

| ID | Сценарий | Достижимый результат и критерий | Зависимость |
|---|---|---|---|
| R2-C01 | Повторить известный анализ | Чистый запуск на опубликованной версии и те же counts/variants/DFG; export содержит версии и хеш входа | Обязательные AC R1 |
| R2-C02 | Узнать степень совместимости с Apromore | Fixed Core SHA + corpus + параметры; таблица совпадений и расхождений по каждому сценарию. Отсутствие oracle означает unverified | Oracle recovery |
| R2-C03 | Импортировать рабочий CSV | Выбор колонок case/activity/time и preview; результат равен эквивалентному XES; ошибки с номером строки сохраняют прежний анализ | Event contract |
| R2-C04 | Осознанно выбрать временную семантику | Source-order или timestamp-order; равные timestamps, timezone и lifecycle имеют отдельный контракт; выбранная политика в export | CSV mapping; normalization contract |
| R2-C05 | Вернуться после перезапуска | Два журнала, IDs, результаты и параметры сохраняются; прерванная запись не повреждает прежние данные | Персистентность и atomic writes |
| R2-C06 | Найти прежний журнал | Список имени/даты/counts/state; одинаковые имена не смешивают результаты | C05 |
| R2-C07 | Восстановить рабочие данные | Backup/restore сохраняет хеши и counts; повреждённый backup отклоняется | C05–06 |
| R2-C08 | Управлять долгой обработкой | Реальные этапы, отзывчивый HTTP и честная отмена; после перезапуска нет бесконечного running | Durable jobs и state recovery |

C01–03 и восстановление oracle могут идти отдельно от хранения. C05–07 образуют последовательную поставку. Если оценка 2–5 дней не подтверждается, R2 делится на R2a «oracle + CSV» и R2b «надёжное хранение». C08 переносится в R3, если надёжное восстановление не укладывается.

R2 — надёжный однопользовательский продукт с доказательствами отдельных сценариев совместимости. Общий сервер, SSO/RBAC, изоляция пользователей, проекты и аудит доступа остаются в R3. Enterprise readiness требует их собственных проверок, а не высокого среднего покрытия функций.

Feature BCR: passed/8, рядом failed и unverified. Успех CSV не компенсирует провал сохранения или восстановления; диагностический отчёт oracle не засчитывается как совместимость.
