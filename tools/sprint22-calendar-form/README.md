# Конечная проверка ошибок календарной формы

`audit-http.py` независимо читает сохранённые ответы C02 и C03, сверяет их
байты и фиксированные ожидания: 2/4 часа, прежний JSON, неизменные сохранённые
настройки и историю, а также отказы при отсутствии прав. Он не запускает
продукт, PostgreSQL, сеть или браузер.

```sh
python3 -I -B tools/sprint22-calendar-form/audit-http.py evidence/sprint22-calendar-form/http-c02 evidence/sprint22-calendar-form/http-c03 audit-result.json
```

Выходной файл должен отсутствовать. Аудитор ограничен 20 секундами,
100 чтениями, 16 MiB суммарно и 2 MiB на файл. Он предназначен для конечного
набора из проверенной копии репозитория; это не общий валидатор архивов
или приватности произвольного дерева файлов.

`check-http.py` — отдельный исполнитель настоящих HTTP-проверок. Он создаёт
синтетические проекты и пользователей, меняет их тестовые права и работает
только с `http://127.0.0.1:3141`. Для него нужен отдельный тестовый PostgreSQL,
свежие каталоги вывода и приватный файл учётных данных вне этих каталогов.
Штатный запуск и остановку стенда выполняет отдельный контроллер.
Ограничения: 48 запросов, 180 секунд, 10 секунд и 2 MiB на ответ; повторов,
прокси и переходов по HTTP-перенаправлениям нет.

Снимки браузера — фактические действия Root и отдельная проверка сохранённых
изображений/AX/DOM другими ролями. HTTP-статус браузерной навигации отдельно
не записывался; 422 подтверждён отдельным HTTP-прогоном. Календарь использует
обычный POST/redirect/reload. Это не проверка Datastar/SSE, всех гонок прав
или всего R5.
