# R5-01: сравнение фильтра по наличию активности

Статус: **проект конечной группы сравнений, до согласования и запуска**. Это вклад в R5-01, не изменение исходных требований и не закрытие всего Core/R5. Новые функции продукта не предлагаются.

Эталон: неизменённый `org.apromore.apmlog.filter.APMLogFilter.filterIndex(List<LogFilterRule>)` из ApromoreCore `bbf24dfd43e72d6992392465f875a4367cbe792b`, canonical APMLogModule JAR SHA256 `4FC0C2CDD170C1F5CBF4FE542250C7B84DEB2DFC583DC10631B6562B3894EF81`, engine class `B07C241D7D5A430F9FD1F6CEA5EB696A71EEFDEE7DC268EE0C81D18C464769B3`. Правило: CASE_EVENT_ATTRIBUTE, RETAIN, ANY_VALUE, ключ `concept:name`, одно буквальное значение активности. Настоящие XLogToImmutableLog/APMLog/PLog/rules и достижимые зависимости обязательны; извлечённый predicate и собственная имитация результата не засчитываются.

Rust: настоящий `filters::apply` с `FilterSpec.case_activity`, остальные поля по умолчанию. Один список правил Java соответствует последовательному применению Rust; отдельный повторный вызов Java сбрасывает исходную выборку и не заменяет композицию.

Общая область сравнения: уникальные непустые trace names, непустые трассы, события с непустыми именами, допустимым временем и явным lifecycle complete. В этой области событие соответствует одному activity instance. Pairing start/complete, malformed/defaulted события и duplicate case IDs не получают credit. Сравниваются полные identities/order/поля сохранённых случаев и событий, а также источник до/после. Метаданные исходного XLog и аналитическая модель Rust описываются отдельно.

До выполнения замораживаются восемь примеров и ручные гипотезы: membership; отсутствие совпадений с пустым результатом; повторяющиеся активности; Unicode с разными регистром/нормализацией; упорядоченная композиция A затем B; отсутствие правил; пустой literal; пустой вход. Первые шесть проверяют выбранное пересечение. Пустой literal имеет разные sentinel semantics (Rust отключает условие, Java ищет пустую строку); это диагностическое различие. На пустом входе настоящий Java converter может отказать до построения filter engine, Rust возвращает пустую модель; такой исход не объявляется исполнением Java-фильтра или equality PASS.

Наблюдатель выводит actual selected trace indices и полные соответствующие исходные случаи; собственный код выбирает их только по результату настоящего engine и не реализует predicate. Доказательства включают exact executable/source/class/dependency/input hashes, native exit и полные потоки, неизменность upstream/source, пустые результаты и все фактические расхождения. Неудачная гипотеза сохраняется. Перед дорогими процессами — точный config review, Job/GO, закрытые каталоги, лимиты/место/срок и живой аудитор; при недоступности настоящего API сохраняется блокер без toy fallback.

Отдельная независимая проверка сравнения и публичная поставка обязательны. Эта работа не доказывает min/max length, event retain/remove, все фильтры Core, IANA/calendar, conversions, качество miner или весь R5.
