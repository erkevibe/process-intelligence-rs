# Process Intelligence Core на Rust

Открытый проект для постепенного переноса поведения Apromore Core на Rust. Первый этап — локальный прототип анализа XES: импорт, статистика, варианты трасс, DFG и интерактивная фильтрация.

Версия 0.3 добавляет фиксированное сравнение с выбранным Java-компонентом Apromore, schema v1/checksum, проверенные восстановление и backup PostgreSQL, а также добавление/удаление задач и переходов BPMN. Независимые QA/TD приняли выбранный артефакт; Совет разрешил публикацию пятью новыми голосами из пяти. Поставка завершена: независимая QA скачала весь публичный архив и проверила SHA256, новую установку и сохранность прежних. [Релиз 0.3.0](https://github.com/erkevibe/process-intelligence-rs/releases/tag/v0.3.0). [План](docs/SPRINT_03_PLAN.md), [отчёт](docs/SPRINT_03_REPORT.md) и [контракт редактора](docs/ui-sprint03-contract.md) показывают результаты, точные идентификаторы и ограничения. Документы внутри frozen ZIP отражают состояние при сборке, актуальный отчёт и release notes — итоговые факты. Прежняя пользовательская установка 0.2 сохраняется отдельно.

Проект в 0.3 может заполниться раньше восьми журналов: проверяется объём JSONB с запасом для отмены и завершения задач. Новый результат при переполнении не сохраняется, прежние данные остаются доступны. Подробности и проверенные границы — в [инструкции восстановления](docs/DATABASE_RECOVERY.md).

Первый спринт завершил рабочее приближение в пределах восьмичасового бюджета 10 октября 2026 года после защиты плана. Работает локальный сценарий XES → статистика → варианты → DFG → порог через SSE → JSON, а также фоновые задачи с отменой и выбор трассы с подсветкой её пути. Независимый QA подтвердил AC01–14 на чистой версии; СОВЕТ FLW принял R1 пятью голосами из пяти. Это первая итерация постепенного развития до enterprise; самостоятельный проект, не официальный релиз Apromore. Enterprise readiness и совместимость с legacy не заявлены.

Версия 0.2.0 прошла независимую приёмку всех 12 выбранных критериев R2–R5 второго спринта с лимитом восемь часов: вход → проект → CSV/XES → фильтры/календарь → BPMN → редактирование подписей и координат → экспорт/резервная копия. PostgreSQL сохраняет данные и параметры после перезапуска; есть owner/editor/viewer и долговечные jobs. СОВЕТ FLW принял точную поставку пятью новыми голосами из пяти. Полные исходные этапы R2–R5, Split Miner и enterprise readiness этим объёмом не закрываются. [Отчёт и доказательства](docs/SPRINT_02_REPORT.md), [ТЗ итерации](docs/SPRINT_02_SPECIFICATION.md) и [план/A01–A12](docs/SPRINT_02_PLAN.md) определяют границы.

## Запуск на Windows

Нужны Git, PowerShell и доступ к официальным источникам загрузки. В каталоге проекта:

```powershell
powershell -ExecutionPolicy Bypass -File tools/setup-windows.ps1
powershell -ExecutionPolicy Bypass -File tools/run-windows.ps1
```

Откройте http://127.0.0.1:3000, создайте первую локальную учётную запись и войдите. Пароль: 12–256 UTF-8 bytes. В разделе «Журналы» загрузите `fixtures/manual.xes`: 4 трассы, 10 событий, 3 действия. При пороге 2 остаются A→B и B→C. CSV требует выбора столбцов; у журнала ссылка «Фильтры и календарь», где строится BPMN. Сервер слушает только loopback. Остановка — Ctrl+C. Другой порт: `tools/run-windows.ps1 -Port 3001`.

Исполняемая Windows-поставка запускается через `Start.ps1`; Rust ей не нужен. Включены PostgreSQL bin/lib/share и лицензии; перед стартом проверяется manifest. Системная служба не устанавливается. По умолчанию HTTP 3000 и PostgreSQL 5433; другие порты: `Start.ps1 -Port 3010 -PostgresPort 5434`. Данные и секреты находятся в защищённом `.local`; не удаляйте его для сохранения БД. PostgreSQL продолжает работать после остановки приложения. Одна Platform instance на БД обеспечивается advisory lease; потеря соединения блокирует защищённые запросы до перезапуска приложения.

Установщик размещает Rust 1.99.0 GNU и LLVM dlltool в `.local`, проверяет SHA256 загрузок и создание импортной библиотеки; глобальные PATH и Rust settings не меняет. Архив LLVM около 191 MB. Если источник rustup-init изменился, проверка хеша остановит установку: нужен проверенный обновлённый manifest, обход проверки не предусмотрен. На Windows используется прямой rust-lld: GNU driver на проверенном окружении терял TLS imports в HTTP harness.

## Запуск на Linux и проверки

С установленным Rust 1.99.0 из каталога проекта; для `cargo run` нужен локальный PostgreSQL и приватная переменная окружения `PI_DATABASE_URL`. Старый режим R1 без сохранения включается только явно через `PI_EPHEMERAL=1`:

```sh
cargo run --locked
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets
```

На Windows для проверок используйте `tools/cargo.ps1`. Для сохранения разделителя `--` в PowerShell передавайте массив:

```powershell
& ./tools/cargo.ps1 -CargoArgs @('clippy','--locked','--all-targets','--','-D','warnings')
& ./tools/cargo.ps1 -CargoArgs @('fmt','--all','--','--check')
& ./tools/cargo.ps1 test --locked --tests
```

Браузерная независимая проверка: `tests/browser-smoke.cjs`; установленные Playwright и Chromium задаются через `PLAYWRIGHT_MODULE` и `BROWSER_EXECUTABLE`. Полные синтетические границы генерирует `tests/generate-boundaries.ps1`. Отчёты спринта хранятся в `flw/evidence`; подробные процессы и сырые HTTP-ответы — приватно в `.local`.

Настоящие PostgreSQL tests `tests/sprint02_platform.rs` запускаются отдельно с `QA_DATABASE_URL`, указывающей на выделенную свежую QA-базу. Обычный `cargo test` честно отмечает их ignored. Запуск: `tools/cargo.ps1 -CargoArgs @('test','--locked','--test','sprint02_platform','--','--ignored','--test-threads=1')`. Не направляйте test/reset в рабочую БД.

Миграционные и fault-проверки находятся в `tests/sprint03_storage.rs`: используются только выделенные `pi_s3_*` базы и приватные `QA_S3_*` переменные, имена проверяются перед операциями. Эти тесты также явно ignored при обычном запуске. Реальные аварии кластера, приложения и native PowerShell bootstrap проверяются отдельно; успешные unit tests их не заменяют. [Обновление, backup и восстановление](docs/DATABASE_RECOVERY.md), [фиксированный oracle](docs/ORACLE.md).

## Исторические границы версии 0.2

Выпуск Windows собирается из чистого архива точного коммита: `tools/build-frozen-windows.ps1 -SourceCommit <SHA> -RunTests`. Скрипт выдаёт путь к доказательству сборки. Упаковка: `tools/package-windows.ps1 -SourceCommit <тот же SHA> -BuildProof <путь> -Version 0.2.0`. Она проверяет версию, исходники и хеш программы; готовый пакет содержит PostgreSQL runtime и лицензии, но не пользовательскую базу или credentials.

До восьми журналов и 64 моделей на проект; прежние лимиты импорта сохраняются. Постоянный проект при заполнении отклоняет новый импорт и сохраняет прежние журналы; для продолжения можно создать другой проект. Параметры представления разделены по пользователям. Две загрузки и две принятые jobs для всей платформы, CPU обработчик mining один. Принятая отмена исключает публикацию; restart переводит незавершённые задачи в interrupted без повторного запуска.

Фильтры сначала выбирают трассы по исходным событиям, затем сохраняют/удаляют действия; пустые трассы сохраняются. Календарь использует фиксированный UTC offset, weekdays, часы и праздники; нет IANA/DST. Без timestamp рабочая длительность unverified. BPMN: один process/start/end/task/XOR/AND/sequenceFlow/DI; остальная семантика отклоняется. `observed_variants_choice_v1` воспроизводит наблюдённые варианты и не обещает обобщения или качества Apromore.

Viewer читает и экспортирует, editor изменяет содержимое, owner управляет membership. Локальные password hashes Argon2id, сессии восемь часов, cookie HttpOnly/SameSite=Strict; до двадцати обработок credentials в минуту. Backup v1 до 20 MiB создаётся после завершения jobs и атомарно восстанавливается в новый проект; credentials/sessions/membership исключены. Сохраняйте исходный файл без пересериализации JSON. PostgreSQL JSONB-документы пока записываются целиком; migrations, общий предел памяти, shared deployment и инфраструктурный recovery относятся к следующим итерациям.

## Исторические границы v0.1 / R1

Журналы хранятся в памяти, последние восемь; перезапуск удаляет их. UTF-8 XES: 20 MiB, 100 000 событий, 20 000 трасс, 4096 UTF-8 bytes на имя действия. Порядок событий — XML; lifecycle не склеивается; DTD, global defaults и nested list/container отклоняются. Фильтр скрывает рёбра и сохраняет исходные counts. JSON содержит полный анализ и текущее представление. Это DFG, который не выводит причинность или параллелизм.

Флажок «Фоновая обработка» включает реальные этапы задачи и отмену. Одновременно принимаются две фоновые задачи; вычисления выполняются по одной. Отмена вступает в силу на безопасной границе обработки, результат принятой отменённой задачи не публикуется. Сохраняются последние восемь завершённых задач и выполняемые задачи. При выборе трассы таблица показывает первые 200 событий; JSON сохраняет все её события. Одновременно буферизуются не более двух загрузок. Эти ограничения не задают общий предел памяти процесса.

## Стек первой итерации

Rust, Axum, Tokio, серверные HTML-шаблоны, Datastar в CSP-режиме, Cytoscape как компонент графа. Rust4PM 0.6.2 скрыт за валидирующим адаптером. UI зависимости обслуживаются локально и закреплены в `static/vendor-manifest.json`. Версия 0.2 добавляет PostgreSQL, CSV, Argon2id, фильтры/календарь и собственный ограниченный BPMN-модуль. Arrow/Parquet и большие данные относятся к будущим этапам.

## Правило готовности

Задача готова, когда проверяемый результат воспроизводится на зафиксированной версии кода. Гипотезы, результаты выполнения и проверенные решения хранятся раздельно. Совместимость с Apromore заявляется только по сценариям, проверенным против конкретной версии legacy.
