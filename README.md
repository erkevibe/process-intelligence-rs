# Process Intelligence Core на Rust

Открытый проект для постепенного переноса поведения Apromore Core на Rust. Первый этап — локальный прототип анализа XES: импорт, статистика, варианты трасс, DFG и интерактивная фильтрация.

Первый спринт завершил рабочее приближение в пределах восьмичасового бюджета 10 октября 2026 года после защиты плана. Работает локальный сценарий XES → статистика → варианты → DFG → порог через SSE → JSON, а также фоновые задачи с отменой и выбор трассы с подсветкой её пути. Независимый QA подтвердил AC01–14 на чистой версии; СОВЕТ FLW принял R1 пятью голосами из пяти. Это первая итерация постепенного развития до enterprise; самостоятельный проект, не официальный релиз Apromore. Enterprise readiness и совместимость с legacy не заявлены.

## Запуск на Windows

Нужны Git, PowerShell и доступ к официальным источникам загрузки. В каталоге проекта:

```powershell
powershell -ExecutionPolicy Bypass -File tools/setup-windows.ps1
powershell -ExecutionPolicy Bypass -File tools/run-windows.ps1
```

Откройте http://127.0.0.1:3000 и загрузите `fixtures/manual.xes`. Эталон: 4 трассы, 10 событий, 3 действия. При пороге 2 остаются A→B и B→C. Сервер слушает только loopback; другая локальная программа может обращаться к API. Остановка — Ctrl+C. Другой порт: `tools/run-windows.ps1 -Port 3001`.

Установщик размещает Rust 1.99.0 GNU и LLVM dlltool в `.local`, проверяет SHA256 загрузок и создание импортной библиотеки; глобальные PATH и Rust settings не меняет. Архив LLVM около 191 MB. Если источник rustup-init изменился, проверка хеша остановит установку: нужен проверенный обновлённый manifest, обход проверки не предусмотрен. На Windows используется прямой rust-lld: GNU driver на проверенном окружении терял TLS imports в HTTP harness.

## Запуск на Linux и проверки

С установленным Rust 1.99.0 из каталога проекта:

```sh
cargo run --locked
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets
```

На Windows для проверок используйте `tools/cargo.ps1`. Для сохранения разделителя `--` в PowerShell передавайте массив:

```powershell
& ./tools/cargo.ps1 -CargoArgs @('clippy','--locked','--all-targets','--','-D','warnings')
& ./tools/cargo.ps1 -CargoArgs @('fmt','--all','--','--check')
& ./tools/cargo.ps1 test --locked --tests
```

Браузерная независимая проверка: `tests/browser-smoke.cjs`; установленные Playwright и Chromium задаются через `PLAYWRIGHT_MODULE` и `BROWSER_EXECUTABLE`. Полные синтетические границы генерирует `tests/generate-boundaries.ps1`. Отчёты спринта хранятся в `flw/evidence`; подробные процессы и сырые HTTP-ответы — приватно в `.local`.

## Границы первой итерации

Журналы хранятся в памяти, последние восемь; перезапуск удаляет их. UTF-8 XES: 20 MiB, 100 000 событий, 20 000 трасс, 4096 UTF-8 bytes на имя действия. Порядок событий — XML; lifecycle не склеивается; DTD, global defaults и nested list/container отклоняются. Фильтр скрывает рёбра и сохраняет исходные counts. JSON содержит полный анализ и текущее представление. Это DFG, который не выводит причинность или параллелизм.

Флажок «Фоновая обработка» включает реальные этапы задачи и отмену. Одновременно принимаются две фоновые задачи; вычисления выполняются по одной. Отмена вступает в силу на безопасной границе обработки, результат принятой отменённой задачи не публикуется. Сохраняются последние восемь завершённых задач и выполняемые задачи. При выборе трассы таблица показывает первые 200 событий; JSON сохраняет все её события. Одновременно буферизуются не более двух загрузок. Эти ограничения не задают общий предел памяти процесса.

## Стек первой итерации

Rust, Axum, Tokio, серверные HTML-шаблоны, Datastar в CSP-режиме, Cytoscape как компонент графа. Rust4PM 0.6.2 скрыт за валидирующим адаптером. UI зависимости обслуживаются локально и закреплены в `static/vendor-manifest.json`. PostgreSQL и Arrow/Parquet относятся к следующим этапам.

## Правило готовности

Задача готова, когда проверяемый результат воспроизводится на зафиксированной версии кода. Гипотезы, результаты выполнения и проверенные решения хранятся раздельно. Совместимость с Apromore заявляется только по сценариям, проверенным против конкретной версии legacy.
