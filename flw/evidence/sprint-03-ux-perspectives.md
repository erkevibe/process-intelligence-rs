# Sprint03 — девять перспектив отдельного PM-источника

Автор /root/pm_final, одно существующее место PM, отдельное от Customer. Это аналитические эмоциональные перспективы FLW, не предположения о чувствах человека и не девять голосов. Read-only snapshot docs/ORACLE.md, docs/DATABASE_RECOVERY.md, текущих src/platform_render.rs/static/platform.js и adopted S3-P1. Первое чтение было частично truncated; строки recovery/outage и actual Save обработчик затем прочитаны отдельно. Скриншоты/браузер здесь не запускались, UX PASS не заявляется. Runtime и frozen oracle/corpus не изменялись.

| Перспектива | Наблюдаемый факт | Проблема | Предложение |
|---|---|---|---|
| Радость | Реальный выбранный Apromore text parser уже дал шесть фиксированных результатов | Общая фраза «совместимо» скрыла бы небольшой, но конкретный результат | Показывать именованные примеры и отдельные совпавшие counts/variants, рядом точные неподтверждённые границы |
| Печаль | Project JSON исключает аккаунты; DB backup содержит auth/session данные, global roles/config не содержит | Один термин «резервная копия» может породить неверное ожидание полного восстановления | Различать копию проекта и базы простыми подписями; перед обновлением явно требовать проверенный отдельный restore и сохранённый private config |
| Гнев | При неизвестном config bootstrap сохраняет кластер и отказывает; actual nativePS5 ошибка была сохранена и исправлена | Повторный запуск не должен вынуждать человека удалять рабочие данные ради успешного старта | Сообщать причину отказа и безопасный следующий шаг с сохранением каталога; не предлагать reset как обычное исправление |
| Страх | Downgrade на upgraded DB не поддерживается; старый0.2 не имеет schema gate | Запуск старого EXE на новой базе может выглядеть как безопасный откат | Инструкция возврата ведёт к исходной БД/config либо проверенному pre-upgrade backup в новую БД; исходную установку не менять |
| Отвращение | Полный database dump включает password hashes/sessions, oracle fixtures синтетические | Публичный отчёт восстановления может раскрыть доступ и пользовательские данные | Публиковать только безопасные hashes/counts/status; сырые backup/credentials/logs с чувствительными данными оставлять приватными |
| Тревога | Timeout сообщает «изменение не подтверждено», допускает complete commit, экземпляр требует reopen | Повтор действия без сверки может создать нежелательный дубль | Сначала reopen и проверка сохранённого результата, затем осознанный повтор; не писать «отменено/откачено» без доказательства |
| Зависть | Полный Apromore имеет более широкие импорт/discovery/filter возможности; выбранный parser принимает нормализованный text | Настоящий narrow oracle легко принять за качество всего miner | В сравнении называть компонент и adapter, исключать importer/timestamp/DFG/BPMN parity и сохранять фактический -1 totalEvents |
| Стыд | Текущий Save вызывает syncField; отдельная «Изменить черновик» переносит node fields в модель | Изменённое поле без Apply может не попасть в saved модель | При Save применять актуальные выбранные поля либо явно блокировать/предупреждать; различать dirty draft и сохранённую revision, проверять reopen |
| Скука | Planned A10 ограничен task/sequenceFlow; текущий экран пока предлагает импорт для изменения topology | Дополнительные действия могут распылиться в произвольный BPMN редактор и съесть резерв | После operational gates дать минимальный add-task/connect/delete-flow/delete-task путь; удаление task явно удаляет incident flows; использовать существующие validation/CAS и stop новые features в final90min |

PM сохраняет плановый приоритет обязательных A03–09: migration/rollback/crash/restore/jobs/deadlines/bootstrap требуют независимой фактической проверки. Эти наблюдения не дают blanket PASS, не закрывают STOP вместо QA/TD и не превращают optional A10 в доказанную функцию. Существующие live3000/3010 и данные сохраняются. Новые экраны и финальный пакет Customer/QA должны посмотреть отдельно.
