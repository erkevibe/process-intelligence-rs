# Sprint07 — отдельный эмоциональный советник FLW

Советник emotional_s7. Основание: отчёт Sprint06 и независимая Customer position Sprint07. Это проверка понятности и доверия к предлагаемому результату, не чтение мыслей пользователя, не реализация и не голос шестого участника Совета. Пользователь разрешил следующий этап с лимитом четыре часа; его удовлетворённость результатом ещё не установлена.

| Перспектива | Факт / риск | Полезное предложение |
|---|---|---|
| Радость | Предыдущий этап дал воспроизводимые реальные результаты; теперь можно показать конкретное изменение импорта. | Один короткий пример «было → осталось», с числами удалённых и дополненных событий. |
| Печаль | После фильтрации пользователь может потерять всю трассу или весь журнал. | Явно показывать «результат пуст» и исходные индексы; не называть пустоту успешным анализом. |
| Гнев | Молчаливое удаление события легко воспринимается как потеря данных. | Только отдельный явно выбранный preview; исходный XML и обычный импорт сохраняются. Каждое удаление получает причину. |
| Страх | Слово «Apromore-compatible» может скрыть непроверенный сервис целиком. | Указывать точную границу: выполнен закреплённый validateLog с реальными XES типами; Portal, persistence и полный сервис не проверены. |
| Брезгливость | Сгенерированный lifecycle=complete может смешаться с исходными данными. | Отмечать default как действие нормализации, отдельно от наблюдавшегося атрибута. |
| Тревога | Четырёхчасовой срок повышает риск подмены реального метода ручной реализацией. | Ранний feasibility gate и резерв на независимый replay; при неудаче честный blocker вместо заявления о совместимости. |
| Зависть | Сравнение с зрелым продуктом может подтолкнуть к искусственной паритетности. | Показывать расхождения и отказы по полям; не ослаблять строгие проверки и не вводить процент совместимости. |
| Смущение | Пользователь может принять инструменты разработчика за новую функцию работающего приложения. | В отчёте прямо сказать, доступен ли режим только через tooling; не выпускать фиктивную Windows-версию. |
| Хандра | Ещё один набор доказательств без понятного результата воспринимается как отсутствие продвижения. | Свести результат к проверенному правилу, конкретному примеру и следующему шагу runtime-интеграции; cleanup оставить отдельным пунктом. |

Поддерживаю Customer S7-C01–C07 как проверяемые требования. Дополнение к финальной приёмке: пример должен показывать отдельно исходное событие, действие нормализации и окончательный результат; полный отсев должен быть заметен даже при нулевых технических ошибках. Совет не даёт разрешения на изменение рабочего импорта, пользовательских БД или установок. Решение о плане и финальном принятии остаётся за пятью фиксированными участниками.
