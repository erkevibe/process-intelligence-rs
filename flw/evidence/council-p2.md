# P2 — восстановление пути сборки и проверок

Фиксированный состав: Root, PM, QA/ProcessLogAuditor, TechnicalDebt/SkillManager, Customer; пять голосов, большинство — не менее трёх. Состав совпадает с P1.

Предложение: возобновить tests/build только через исправленный путь прямого rust-lld + llvm-dlltool, область ENV-OBS-03. Прежние аварийные exe исключены из рабочего пути. Решение не является приёмкой релиза.

Доказательства: независимый TechnicalDebt локализовал отсутствующие loader-visible TLS imports в HTTP harness. После прямого LLD imports восстановлены; actual wrapper run `.local/logs/wrapper-contract-tests-06.log` завершился exit 0, core 8 PASS, HTTP 6 PASS. Условия тестов не ослаблены. Приватные подробности и публичная оценка — `debt.md` и QA inventory.

Голоса получены от реальных агентов:

- Root: за, на основании actual wrapper run и восстановленной структуры импортов.
- QA: за; независимо прочитал весь журнал и wrapper, отдельно сохраняет browser blocker до повторного smoke.
- TechnicalDebt: за точный P2; независимо прочитал журнал и фактически запущенный PE, linker 14.0, TLS imports присутствуют.
- PM: за; прочитал actual wrapper flags и оба успешных журнала; собственную PE-проверку не заявляет.
- Customer: за; прочитал actual wrapper log и независимое заключение TechnicalDebt, требует pin и clean start до сдачи.

Решение: пять голосов из пяти. Первоначальные три голоса уже дали требуемое большинство; два дополнительных голоса подтверждены отдельными агентами. Tests/build возобновляются на исправленном пути. Непроверенный pin, browser smoke и итоговый кандидат остаются отдельными обязательствами; release acceptance не объявляется.
