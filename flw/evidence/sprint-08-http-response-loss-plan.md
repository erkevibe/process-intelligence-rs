## Проспективный конечный протокол

1. До воздействия QA фиксирует точные input bytes/hash, параметры, полный report и URL/UUID, права/session, состояние исходных журналов, полный SQL baseline (values+versions), source-path equivalence с предыдущими доказательствами preview/default/refusal/limits/expiry/cancel. Исторический результат переиспользуется только по полному именованному затронутому пути и явно объявленной области; недостающие текущие проверки не маскируются.
2. Одноразовый локальный HTTP-прокси только на127.0.0.1 и свободном порту пересылает ровно одно корректное авторизованное подтверждение в свой backend. Не повторяет запрос автоматически. Записывает фактический полный upstream303/Location/время/hash до намеренного закрытия downstream без ответа. Credentials/bind parameters только в защищённых частных файлах; публично безопасные hashes/shape. TD проверяет исходник инструмента до воздействия; если успех не наблюдён или граница не установлена, не засчитывать тест.
3. Клиент фактически получает обрыв/ошибку транспорта и не видит303/Location. Отдельным прямым чтением QA доказывает ровно один durable log с данным UUID, original SHA, policy/actions/date, один успешный audit и сохранность всех прежних heavy values+versions. Live повтор с тем же токеном возвращает тот же ID без второй записи/audit. Отмена после успешного подтверждения не заявляется.
4. После фактического перезапуска только собственного приложения старый токен отказывает. По сохранённым UUID+полным SHA и доступной истории оператор вручную находит тот же результат; полный raw/actions/policy/date и анализ сохраняются. Не загружать повторно. Недоступность списка/истории сама по себе не доказывает отсутствие COMMIT; при невозможности сверки результат остаётся неопределённым.
5. QA/TD отдельно фиксируют actual native handles/creation/path/hash/exits, ошибки и continuations, полные inputs/outputs и conservation. Customer проверяет конкретную ручную процедуру. Новый Совет решает, закрыт ли весь исходный конечный R2-03 по совокупности доказательств. Успех только HTTP-ветви не равен полному PASS, не заменяет DB-COMMITack и не закрывает весь R2–R5.
